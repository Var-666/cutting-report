# 20261106-v1 服务器程序更新

适用于已经完成 SQLite → PostgreSQL 切换、默认五个容器正常运行的服务器。用户已确认现场完成切换；本次不重新导入 SQLite，也不重复运行 `prepare-consumers`。首次切换仍看[首次升级说明](服务器首次升级说明.md)。

## 本次变化

- 管理员车间、设备报表默认查询当天，不再自动回退到最近有生产数据的日期。跨日返回时清除旧任务/旧范围汇总；当天无数据展示空状态。手动历史查询及工人确认的既有日期规则保留。
- 修复完成趋势下钻：某天只有加工完成记录时，点击日期或图表空白列打开完成明细；点击派发/完成柱仍按对应类型查询，避免重复请求。
- 工程号、船名、分段名缺失统一显示`--`，覆盖车间、设备、批量确认及个人确认记录；已有字段值不变。派发历史标识列去除额外代码样式，业务内容保留。
- 承接v5的唯一任务ID完成关联、两种机床字段兼容、失败诊断与Consumer诊断；本次后端/API契约、依赖、数据库结构均未改变，仍为PG006。前端随本包重新构建，需同步更新完整程序及前端资源。
- Python/前端依赖锁、Dockerfile、基础 Compose、四角色启动脚本与 20261104-v1 一致。复用当日已导入的 `cutting-report:local` 和 `postgres:18.6-bookworm`，本包不重复附带镜像。20261030 及更早镜像不可用。
- 私有 `.env` 共 128 项，与当前示例完整对应，相较20261105-v5逐值不变；回调开启，允许来源 `10.147.1.41`。该地址取自用户提供的魔盒网页 `10.147.1.41:8080`，实际通知来源须现场测试确认，端口不写进白名单。
- 能管、HR、文件库、魔盒推送、回调、模型、告警及自动化八项开启。焊接缺连接、SMTP缺邮箱参数、SQL工作台缺管理员Token，继续关闭。端口8088、一个Consumer、告警30天、后台300秒、模型并发10不变。
- 不覆盖数据卷中的 `data/settings.env`；它仍优先于 `.env`。本包保留上包 PG 密码，已有 PG 不能通过改环境变量直接修改数据库角色密码。

## 文件放置

把 `cutting-report-kylin-offline-docker-20261106-v1.zip` 及同名 `.zip.sha256` 上传到 `/opt/cutting-report-kylin/`。在该目录执行：

```bash
sha256sum -c cutting-report-kylin-offline-docker-20261106-v1.zip.sha256
unzip cutting-report-kylin-offline-docker-20261106-v1.zip
cd cutting-report-kylin-offline-docker-20261106-v1
```

默认旧部署目录为已完成上次升级的 `20261104-v1`。若现场使用其他目录，将其作为更新脚本的第一个参数，不要填写本次新目录。

## 一键更新

本包已内置 `scripts/linux/update_offline_docker.sh`，不需要单独上传脚本。在新目录以root执行：

```bash
bash scripts/linux/update_offline_docker.sh
```

默认旧目录为 `/opt/cutting-report-kylin/cutting-report-kylin-offline-docker-20261104-v1`，备份保存到 `/data`。如果实际旧目录不同，作为第一个参数传入：

```bash
bash scripts/linux/update_offline_docker.sh /实际旧部署目录
```

脚本在停服前核对已有PG、项目和数据卷、包内程序文件完整性以及新旧PG凭据；允许修改包内.env中的部署配置，但PG连接和密码必须保留现场值。随后暂停本项目四个应用角色、备份PG和文件、追加缺少的迁移并启动/检查健康。不下载镜像，不重复SQLite导入，不运行prepare-consumers，不操作其他项目。

失败即停止后续步骤并打印阶段和备份位置；新服务启动/健康失败会停止四个新应用角色。保留输出及备份，不运行down -v，不删除卷或只换旧目录回退已升级PG。查看日志：

```bash
docker compose logs --tail 100 app scheduler worker automation
```

本次更新前端页面和预加载，.env、镜像、后端及PG结构与v5保持一致。脚本仍执行停四角色、完整备份、迁移检查和启动，未自动简化为快速替换。若现场当前运行目录为20261105-v5或其他版本，将该实际目录作为脚本第一个参数，备份才能准确保留当时的配置。

## 魔盒回调现场配置

魔盒主动向本项目发送通知。将“任务完成”接收地址配置为：

```text
http://<项目服务器IP>:8088/api/v1/magic-box/callbacks/task-finished
```

`10.147.1.41:8080` 是魔盒网页地址；截图里的 `http://10.147.1.61/api/dingheng/callback/taskFinish` 是现有接收地址，**与本项目路径不同**。本次打包不修改魔盒配置，也不假定现有路径会转发到本项目；由魔盒方新增本项目接收地址，或明确配置对应的反向代理。已有接收项先保留。

先用魔盒“测试通知”检查 HTTP 200 与应答 `{"status":0,"msg":"OK"}`；如果来源经过代理/NAT、与网页IP不同，按服务端实际连接来源修正 `MAGIC_BOX_CALLBACK_ALLOWED_IPS` 并重建应用容器。未完成测试前不能认为通知已接通。真实任务仍须回传本系统上传的唯一 `taskIdentifier` 和有效完成机床信息；完成机床可以不同于原目标机床，旧通知不自动补发。
