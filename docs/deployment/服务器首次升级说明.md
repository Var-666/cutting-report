# 20261104-v1 公司麒麟服务器完整离线部署包

本包基于 aade9ed，包含当前程序、前端、私有 .env 及 AMD64 应用/PostgreSQL18.6 镜像。旧服务器无需联网下载 Python、Node、Chromium 或镜像。只适用于同机 x86_64/amd64 Docker 部署。

**这是首次状态库与后台协议升级，不是以前替换程序后直接启动的更新。** 20261103-v3及更早版本仍用SQLite，必须先停机备份、整理现场配置、导入并校验全部历史数据，再运行Consumer准备并启动新版本。不要只执行旧的 start_offline_docker.sh。已有PostgreSQL现场按 docs/deployment/WEB_WORKER进程隔离升级说明.md 升级，先保留原PG账号密码，不要用本包新密码覆盖既有账号。

## 环境变化和开关

- .env由旧145项迁移为当前126项：补入30项新配置，49项旧连接/设备变量归入PRODUCTION_LINES_JSON、DATABASE_SOURCES_JSON等正式配置。原切割、HR/PDM连接及密码、仪表、告警起点按原配置转换，不猜测新库。
- 能管、HR认证、文件库、魔盒、模型、告警、自动化7项开启。焊接产线/数据源缺连接参数仍停用；SMTP缺邮箱参数、SQL工作台缺管理员Token仍关闭。不要把“开关=true”当作真实连接成功。
- 新增PostgreSQL三个不同密码、cutting_app/cutting_migrator账号分工；默认每进程池4。新增Scheduler/Automation及Consumer配置，先保留1个Consumer，操作4/分析10。端口8088、告警30天、刷新300秒保留。
- PostgreSQL只在Docker内部使用，不发布5432端口；不登记为生产数据源。data/settings.env优先，已保存的现场配置必须保留并迁移，可能覆盖包内.env。
- 原Docker存储若已迁到/data/docker，继续使用，项目目录不必更改。建议将本包和备份放/data，避免再次挤满根分区。

## 一键首次升级

将 `upgrade_offline_docker.sh` 放入新包 `scripts/linux/`，在新包根目录以root执行：

```bash
bash scripts/linux/upgrade_offline_docker.sh
```

默认旧目录已按现场确认为 `/opt/cutting-report-kylin/cutting-report-kylin-offline-docker-20261103-v2`，备份位于 `/data`。脚本自动校验镜像、核对真实卷/空间、停旧服务、保留旧镜像、备份、迁移现场配置、准备PG、导入和verify、prepare-consumers以及启动/健康检查。无需重新输入数据库密码。也可显式传入旧目录和备份所在目录作为两个参数。

只支持这次首次SQLite升级；发现已有PG目标卷会在停旧服务前拒绝，不会清空或覆盖它。中途失败请保留终端输出和脚本打印的备份目录，先核对状态，不要删除卷后强行重试。新服务健康失败会停止新角色，保留数据库和备份，不自动回退旧SQLite。整个过程会短暂停止本项目，不操作其他项目。

租约检查保留SQLite只读连接，但数据目录须允许应用账号创建WAL辅助文件；旧脚本若在该步骤报unable to open database file，替换最新脚本后重跑。此时尚未进入数据归档/导入，新运行会建立新的完整备份。不要以immutable方式跳过WAL。

下方手工步骤用于理解和故障核对；使用一键脚本后不要再重复执行这些迁移。原20261104-v1 ZIP保持不变，已有包只需补入脚本；后续新包由文件清单收录。

## 1. 解压和导入离线镜像

将ZIP上传至/data，解压后进入新目录：

```bash
cd /data
unzip cutting-report-kylin-offline-docker-20261104-v1.zip
cd cutting-report-kylin-offline-docker-20261104-v1
sha256sum -c SHA256SUMS
docker load -i images/cutting-report-images-amd64-20261104-v1.tar.gz
```

镜像包同时装入 cutting-report:local、cutting-report:runtime-20261104-v1 与 postgres:18.6-bookworm。offline Compose使用版本标签且禁止拉取，避免docker save/load后缺少registry digest而再次联网。

## 2. 停旧服务并备份（首次SQLite升级）

将old_dir改成**实际正在运行的旧部署目录**，不能填新包目录。确认旧项目为cutting-report、实际卷为下列名称；若使用自定义卷名，先按docker inspect核实并替换，不能误连空卷。

```bash
set -e
old_dir=/opt/cutting-report-kylin/cutting-report-kylin-offline-docker-20261103-v2
test -f "$old_dir/.env"
test -f "$old_dir/compose.yaml"
docker volume inspect cutting-report_cutting_data cutting-report_cutting_reports cutting-report_cutting_logs >/dev/null
(cd "$old_dir" && docker compose stop)
# 等待旧Worker有效租约释放/到期，至少35秒，再继续。
sleep 35
backup_dir="$(mktemp -d /data/cutting-before-20261104-XXXXXXXX)"
chmod 700 "$backup_dir"
cp -p "$old_dir/.env" "$backup_dir/env.before"
docker run --rm --user 0:0 --network none \
  -v cutting-report_cutting_data:/app/data:ro \
  -v cutting-report_cutting_reports:/app/reports:ro \
  -v cutting-report_cutting_logs:/app/logs:ro \
  -v "$backup_dir:/backup:z" \
  cutting-report:runtime-20261104-v1 \
  tar -czf /backup/app-files.tgz -C /app data reports logs
```

以上只停止旧目录所属Compose项目，不停止公司其他Docker项目。保留旧程序/镜像和本次备份，不执行down -v或清空卷。任一命令失败即停止后续操作，不把失败备份当作成功。

## 3. 迁移现场配置，然后准备PG、导入并校验

先用旧目录.env和同一数据卷中的settings.env迁移，保留现场实际连接，不能让新包的默认绑定替代现场配置。维护容器临时以root读取旧.env，结束时将应用配置和锁文件交还镜像内app用户；不会连接生产数据库。

```bash
# 仅创建子挂载点，真实数据仍来自原Docker卷。
mkdir -p "$old_dir/data"
docker run --rm --user 0:0 --network none -e APP_DATA_SOURCE_MODE=sqlserver \
  -v "$old_dir:/legacy:ro,z" \
  -v cutting-report_cutting_data:/legacy/data \
  -v cutting-report_cutting_data:/app/data \
  cutting-report:runtime-20261104-v1 sh -ec '
    python scripts/migrate_production_lines.py --root /legacy
    for f in /app/data/settings.env /app/data/settings.env.lock /app/data/.web-process.lock; do
      if [ -f "$f" ]; then chown app:app "$f"; fi
    done
  '

docker compose -f compose.yaml -f compose.offline.yaml up -d --no-build --pull never postgres
docker compose -f compose.yaml -f compose.offline.yaml run --rm --no-deps -T migrate python scripts/migrate_sqlite_to_postgres.py schema
docker compose -f compose.yaml -f compose.offline.yaml run --rm --no-deps -T migrate python scripts/migrate_database.py upgrade --database /app/data/metadata.db
docker compose -f compose.yaml -f compose.offline.yaml run --rm --no-deps -T migrate python scripts/migrate_sqlite_to_postgres.py check --sqlite /app/data/metadata.db
docker compose -f compose.yaml -f compose.offline.yaml run --rm --no-deps -T migrate python scripts/migrate_sqlite_to_postgres.py migrate --sqlite /app/data/metadata.db
docker compose -f compose.yaml -f compose.offline.yaml run --rm --no-deps -T migrate python scripts/migrate_sqlite_to_postgres.py verify --sqlite /app/data/metadata.db
```

必须确认migrate、verify均输出result=verified；目标必须为空或与同一快照一致。工具拒绝未知目标、有效租约和缺失实体文件，不要绕过保护。原SQLite保留为归档，不再作为第二状态库。若settings.env存在旧POSTGRES_*值，应先按实际PG角色同步，不能通过不断重试或删除PG卷处理认证失败。

## 4. 显式切换Consumer协议，再启动

仅在导入/verify成功、旧服务仍停止时执行：

```bash
docker compose -f compose.yaml -f compose.offline.yaml run --rm --no-deps -T migrate python scripts/migrate_sqlite_to_postgres.py prepare-consumers
./scripts/linux/start_offline_docker.sh
docker compose ps
docker compose logs --tail 100 app scheduler worker automation
curl --fail http://127.0.0.1:8088/api/v1/health
```

prepare-consumers会恢复中断执行态并阻止无可信来源的旧任务，保留业务ID、重试和历史记录；不能先改变执行态再与原SQLite做全字段verify。正常启动不自动建表、导入或准备协议。后台为Scheduler+1个Consumer+Automation，Web同源提供页面/API；Consumer不再固定名为cutting-report-worker，应使用docker compose logs worker。

检查四角色健康、background_ready=true、登录/权限、历史报表/确认/告警、文件引用与自动化状态；再完成现场生产库、能管、模型及PDM/魔盒只读联调。网页已保存连接/启用状态优先，包内开关不代表所有现场服务接通。

## 5. 回退与注意

切换前的SQLite、配置、实体文件、旧镜像须同批保留。新版本一旦产生确认、邮件、告警等记录，不能仅换旧镜像或改.env回SQLite；先停全部应用角色、备份PG和文件，再按差异制定回迁方案。不要删除版本标记、清空PG或自动重发unknown结果。详细步骤见docs/deployment/PostgreSQL状态库迁移.md及WEB_WORKER进程隔离升级说明.md。

本包包含私有.env，只供指定公司服务器使用，不提交Git或公开分发。开发机仅进行了隔离演示验证，未执行生产切换、真实派发或邮件发送。
