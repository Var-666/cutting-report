## 来源优先级与生效诊断

统一优先级保持为 `data/settings.env > 进程环境变量 > 项目 .env > 程序默认值`。管理页面只是写入 `data/settings.env` 的入口，不存在第四份存储。项目 `.env` 使用原有变量展开规则（进程环境优先）；`settings.env` 的值按字面读取，不展开 `${...}`。保留 `PYTHON_DOTENV_DISABLED` 的启动禁用行为。

产线实例、物理机号、范围、仪表及告警起点只取 `PRODUCTION_LINES_JSON`；SQL Server/MySQL 连接只取 `DATABASE_SOURCES_JSON`。实例通过 `source_key` 绑定连接。旧 `DEVICE_CONFIG_PATH/devices.json`、`SQLSERVER_*`、`WORKER_SQLSERVER_*`、`FILE_SQLSERVER_*`、`WELD_*` 只由一次性迁移工具读取，正式应用不会回退读取它们。
- 自动化与 SMTP：管理保存后 Web 原子发布运行快照，各后台角色按文件版本在下一轮操作加载；在途操作保持原快照。无效文件或参数保留上次可用热配置并显示异常。
- 数据库页配置：统一产线目录、数据源连接参数、生产数据模式及 HR/文件库开关保存到 `data/settings.env` 后，Web 新请求和三个后台角色下一次操作自动加载；在途查询继续使用原连接。单源 `sql_max_concurrent` 为冷配置，须同时重启所有应用进程。参数不完整或文件无效保留上次快照，诊断读取本身不触发更新。
- `REPORT_BACKGROUND_REFRESH_SECONDS`：写入同一 `data/settings.env` 后按原数据库快照热加载；切割与焊接按新间隔调度，沿用最小30秒。不增加配置监听器或页面入口，其他调度/告警/保留参数的重启规则不变。
- 模型、能管、文件服务、告警/保留策略及其他启动参数：重启 Web、Scheduler、Consumer、Automation 生效；产线目录及单源连接池/超时已在 P1 中纳入热加载。
- Docker 宿主机 `.env` 变更：执行 `docker compose up -d --force-recreate app scheduler worker automation`；源码更新需加 `--build`。`restart` 不会刷新已有容器的环境。先检查 `data/settings.env` 是否覆盖同名参数，不删除配置或数据卷。

管理员打开“系统设置 → 配置诊断”（`GET /api/v1/configuration/diagnostics`）默认只展示异常配置，可按分类和名称筛选并分页，分别查看 Web、Scheduler、Consumer、Automation 当前快照、来源、已保存目标、加载批次和热修订。`PRODUCTION_LINES_JSON`、`DATABASE_SOURCES_JSON` 及显式绑定键参与真实值比较，不再展示旧连接继承链。密码、账号、密钥、Token、Cookie、URL 等只返回已配置/未配置；不返回明文或内部逐项比较指纹。

“已生效”表示实际快照与该进程环境下的保存目标一致；冷配置差异显示“待重启”，无效参数、热配置未加载或 各角色值不同显示“配置异常”。三个后台角色各用独立心跳，缺失、停止、过期或旧版本未上报时显示未知/异常，不借用 Web 快照。界面版本号标识加载批次，一致性通过实际值逐项比较（包含凭据变化），不能比较脱敏文字或仅看版本号。

诊断接口只读，不触发热加载、重连数据库或后台操作，也不验证外部服务连通性。宿主机尚未注入容器的新 `.env` 不可从容器内获知；先重建所有应用容器，再用诊断页核对来源、各角色状态和覆盖项。诊断异常不会阻断登录或普通报表查询。

现行保留默认值为报告365天、分析90天、告警发生后30天且已解除、非活动派发365天、审计730天、下载实体7天；对应天数0关闭该类清理。具体边界见下方“数据保留”。

P7 部署为单 Web、单 Scheduler、1～N个同机 Consumer、单 Automation，默认1个Consumer。当前版本已移除SQLite升级/导入，旧部署须先使用保留的历史版本完成迁移；旧PG全局Worker协议仍需停机后显式prepare-consumers，普通更新不重复执行；启动命令、独立探针及回退见 [四角色部署说明](WEB_WORKER进程隔离升级说明.md)。

## SQL 与 HTTP 资源容量

PostgreSQL 状态库使用独立的冷配置 `POSTGRES_HOST/PORT/DATABASE/USER/PASSWORD`、`POSTGRES_POOL_MIN_SIZE/MAX_SIZE`、`POSTGRES_CONNECT_TIMEOUT_SECONDS`。P6四个应用角色统一使用PostgreSQL，每进程独立复用默认0–4连接池，N个Consumer时应用总上限4×(N+3)，另预留探针/维护连接，不回退SQLite；不加入生产数据源目录。配置默认值、三个隔离账号、首次停机迁移与恢复流程见 [PostgreSQL状态库迁移](PostgreSQL状态库迁移.md)。

SQL Server 与 MySQL 在驱动入口统一获取全局、数据源和稳定产线 ID 的配额，直到连接关闭或只读事务归还连接后释放。所有同机应用实例必须共享同一 `data/.coordination/sql` 本地目录；固定文件槽及 OS 文件锁协调容量，进程退出释放锁，不向状态库写配额表。只支持当前单机共享本地卷部署，不用于多主机或网络文件系统。

| 参数 | 默认值/作用 |
| --- | --- |
| `SQL_GLOBAL_MAX_CONCURRENT` | 12，所有应用实例合计 SQL 执行上限 |
| `SQL_GLOBAL_MAX_WAITERS` | 32，共享 SQL 等待槽；0 表示不排队 |
| `SQL_QUEUE_TIMEOUT_SECONDS` | 5 秒，SQL 等待预算 |
| `SQLSERVER_DEFAULT_MAX_CONCURRENT` | 6，单 SQL Server 源默认容量 |
| `MYSQL_DEFAULT_MAX_CONCURRENT` | 4，单 MySQL 源默认容量，同时受连接池大小限制 |
| `SQL_LINE_MAX_CONCURRENT` | 2，单产线 SQL 容量；HR/PDM 等共享用途不绑定虚构产线 |
| `HTTP_QUERY_MAX_CONCURRENT` / `HTTP_SNAPSHOT_MAX_CONCURRENT` | 12 / 4，进程内现场查询/快照请求执行池 |
| `HTTP_ANALYSIS_MAX_CONCURRENT` / `HTTP_PDF_MAX_CONCURRENT` / `HTTP_AUTH_MAX_CONCURRENT` | 10 / 2 / 8，进程内分析/PDF/认证请求执行池 |
| `HTTP_MAX_WAITERS` | 32，每个 HTTP 执行池的等待上限 |

在 `DATABASE_SOURCES_JSON` 的单源对象或数据源管理 API 请求中设置 `sql_max_concurrent`（1–64，null 使用引擎默认值）覆盖单源容量；全局上限和 MySQL 本地池限制仍有效。所有容量参数为冷配置，修改后同时重启所有应用进程，避免角色采用不同上限；单源连接选项仍按原规则热加载。资源容量变化不改变报表来源身份、数据版本或历史快照。

HTTP 与 SQL 等待共用请求中的排队预算，并计入原操作总期限。队列满或 SQL 排队超时返回 503、`Retry-After: 1` 和 `X-SQL-Resource-Error`；HTTP 执行池拒绝使用 `X-Workload-Error`。SQL 排队耗尽原操作总期限时返回 504、`OPERATION_TIMEOUT`，同时计入资源等待超时数。请求取消/断连释放等待位置。SQL 配额在数据准备结束后释放，模型和 Chromium 继续使用各自已有资源控制。

管理员只读 `GET /api/v1/database/resources` 返回 Web 本进程 SQL/HTTP 状态，保留 worker 字段，并在 roles 中提供各后台角色及worker:实例ID最近心跳的 SQL 状态（无采样为 null），包括执行/等待数、上限、超时及拒绝计数。`scope=process` 表示这些计数各自属于一个进程，不能相加声称实时全局统计；共享执行上限由文件锁保证。单源 `configured_capacity` 与 `execution_capacity` 不同时显示 `restart_required`，配置诊断也提示待重启。Worker 缺失或过期须结合 `worker_state` 判断；不返回连接凭据、SQL 或参数。

## Consumer实例与容量（P7）

| 参数 | 默认值 / 作用 |
| --- | --- |
| CONSUMER_INSTANCE_ID | 空；Docker用自身hostname，原生必须显式设置唯一ID，1–64位字母/数字/点/下划线/连字符；不要保存在共享settings.env |
| CONSUMER_REPLICAS | 1；Compose副本数量及Web最小健康Consumer期望值，至少1，冷生效；--scale仅覆盖实际数量，不改变健康期望 |

本地执行槽与共享SQL/模型/PDF容量不同，扩容不能绕过P3上限。配置诊断只展示当前运行或停滞的Consumer实例快照，不列出容器重建留下的lost/stopped历史记录，也不将其计入配置异常；正常运行数量不足或当前实例异常仍会提示。历史租约继续保留给任务恢复和原清理流程；CONSUMER_INSTANCE_ID不参与共享配置一致性比较。单实例探针、失效记录保留、停机升级与扩缩容命令见[部署说明](WEB_WORKER进程隔离升级说明.md)。

## 魔盒加工完成回调

项目接收地址为 `POST /api/v1/magic-box/callbacks/task-finished`，在魔盒“系统设置 → 回调地址设置”中配置给 `TASK_FINISHED`。这是魔盒调用项目服务器的地址，不能填成魔盒自己的地址。

```dotenv
MAGIC_BOX_CALLBACK_ENABLED=false
MAGIC_BOX_CALLBACK_ALLOWED_IPS=
```

默认关闭。启用前按停机维护流程，通过现有 `scripts/manage_postgres.py schema` 应用 `005_dispatch_file_location` 和 `006_dispatch_completion` 等尚未应用的迁移；不在普通启动或回调请求里建表。将允许来源配置为实际发送回调的魔盒服务器具体IP（多个用英文逗号分隔，不接受网段），再设置 `MAGIC_BOX_CALLBACK_ENABLED=true` 并重启应用进程。这两个参数为冷配置，不通过管理页热加载。

入口不使用浏览器登录Cookie，只接受配置的网络对端IP。若经过代理，须在受控代理上保留并校验真实来源，不能把任意转发头当作来源认证。

项目校验并提交数据库后自动返回HTTP 200和 `{"status":0,"msg":"OK"}`，无需人员手动回复。该JSON沿用魔盒原API的成功格式，回调文档未明确应答格式；现场通过真实任务完成通知核对HTTP、应用日志及对应任务入库结果。若魔盒版本提供测试通知可先测试，不依赖配置页一定存在该按钮。通知失败后的恢复按魔盒实际功能处理，不能假定历史漏通知会自动补发。

回调按 `taskIdentifier` 精确匹配唯一的本系统真实已上传派发任务，不要求完成机床IP与派发目标IP一致；模拟记录、未上传任务和标识不唯一的记录不会被标记完成。`FinishBy`（也接受小写开头 `finishBy`，两者同时存在时以 `FinishBy` 为准）仅作为实际完成机床信息保存，不覆盖原目标机床。机床字段仍按文档校验格式，缺失、空值及无效IP继续拒绝。测试通知中的空标识和其他系统任务会正常应答但不更新任务，日志提示未匹配，现场须确认真实通知能回传上传时的任务标识。重复通知保留首次完成时间及完成机床，不增加次数；数据库写入失败不会应答成功。

2026-11-05现场HTTP抓包确认：任务完成报文使用 `finishBy` 小写开头，文档示例为 `FinishBy`；另含 `eventType=TASK_FINISHED`、`machineIp`、`machineType` 和 `taskUuid`。这些附加字段不参与当前完成匹配，`taskUuid` 是魔盒任务UUID，不能代替本系统派发的 `taskIdentifier`。比较机床或排查记录前须核对同一任务ID。

若访问日志出现422，查询 `docker logs --since 24h cutting-report 2>&1 | grep '魔盒完成通知校验失败'`。校验失败时仍可取得请求JSON：日志记录来源、Content-Type、请求体类型、前20个字段名（各最多80字符）、失败字段及数据类型，并在 `callback_body` 保留机床、完成时间、任务标识、任务名称、材质及厚度的原始标量值（字符串各最多512字符，识别大小写/下划线变体用于排查；对象/数组仅记录类型）。不记录其他字段值、完整请求或授权头。需更新程序后才生效，旧访问日志无法还原失败载荷。按真实字段错误修正并联调，不能仅为消除422跳过任务、机床或时间校验；此前失败的通知须由魔盒补发或另行核实，不能假定自动补录。

完成回调仅更新本系统PostgreSQL中的加工完成信息，不回写生产库或PDM。魔盒未发出通知、通知尚未接入或历史通知缺失时，项目不推测加工状态。页面可见时每5秒静默更新当前明细与趋势，离开页面停止，隐藏标签页不发轮询请求。

### OIDC 统一认证

SSO 默认关闭。启用后，本站登录页仍使用原账号密码表单，不显示统一认证按钮，也不自动跳转。认证中心门户中的本站入口指向 `http://本站地址/api/v1/auth/sso/login`，通过此入口发起统一认证；回调地址单独登记为 `/api/v1/auth/sso/callback`。所有 SSO 参数为冷配置，沿用本文配置优先级，修改后重启应用进程，不通过管理页热加载。现有本地/HR登录、管理员授权和业务接口权限不变。

| 参数 | 默认值/作用 |
| --- | --- |
| `SSO_ENABLED` | `false`；开启统一认证 |
| `SSO_ISSUER` | 空；认证中心实际签发的 issuer，与 Discovery 和 ID Token 中的值严格一致 |
| `SSO_CLIENT_ID` | 空；产报系统独立登记的客户端 ID，例如 `report-system` |
| `SSO_CLIENT_SECRET` | 空；该客户端独立密钥，仅保存在服务器，不提交到 Git |
| `SSO_REDIRECT_URI` | 空；完整回调地址，例如 `https://report.example.internal/api/v1/auth/sso/callback` |
| `SSO_ACCOUNT_BINDINGS_JSON` | `[]`；HR账号无需逐个填写；特殊/本地账号可填 `[{"sub":"认证中心实际主体标识","user_id":"本站已有账号ID"}]`，主体与账号必须一对一 |

在认证中心 `AUTH_CLIENTS` 登记同一客户端 ID、密钥和完整回调地址。浏览器与 Web 后端均须能访问认证中心；浏览器须能访问回调域名，代理须转发 `/api/v1/auth/sso/`。后端从 `SSO_ISSUER` 下的 `/.well-known/openid-configuration` 读取授权、令牌和 JWKS 地址，使用授权码、S256 PKCE 和 `client_secret_basic`，当前支持 RS256 ID Token；时间声明（iat/nbf/exp）允许最多30秒时钟偏差，超过容差仍拒绝，签名、issuer、受众及nonce校验保持开启；其他签名算法不降级接受。按实际 issuer 精确配置尾斜杠。

指南中的认证中心地址为 `http://10.147.0.23:15374`，实现允许按该内网约定联调；HTTP不提供密码、密钥及令牌的传输保护，正式部署应与认证中心共同确认 HTTPS。本站启用 HTTPS 后设置 `AUTH_COOKIE_SECURE=true`；HTTP本站不能开启此项。参考 [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html) 和 [PKCE](https://www.rfc-editor.org/rfc/rfc7636)。

现场已确认产报客户端的 `sub` 等于 HR 人员库 `_Identify`。没有显式绑定时，按已验证令牌中的 `sub` 精确查找本站 `auth_source=hr_database` 且 `external_id=sub` 的已启用账号，包括从 HR 授权的管理员；继续使用原账号ID、角色及业务历史，无需逐个填写绑定。不按姓名、工号或令牌角色匹配，也不创建、启用账号或授予管理员权限。每次HR来源账号完成SSO认证时，重新读取人员可用状态及最新姓名、集团工号和公司工号；资料刷新与本站会话创建在同一事务内提交，再次核对账号仍启用且身份未变化。HR故障时拒绝本次认证；普通会话继续沿用原复核间隔。

本地账号或其他特殊映射仍可显式绑定：用管理员身份通过现有 `/api/v1/auth/users` 查询本站账号 ID，并核实产报客户端实际签发的 `iss/sub` 后填写。显式绑定优先，已显式绑定的账号不再接受另一个 `sub` 自动对应；无效显式绑定不回退自动匹配。账号不存在或已停用时拒绝登录。首次初始化管理员仍使用原流程。`sub`、HR主键语义或 issuer 变化须重新核实对应关系，不直接复制其他客户端收到的主体标识。

发布前按现有停机维护与备份流程，用 `cutting_migrator` 执行 `scripts/manage_postgres.py schema`，应用 `007_sso_requests` 及必要授权；普通启动和请求不建表。一次性登录状态只保存于应用 PostgreSQL，绑定浏览器、有效5分钟、回调原子消费，最多保留1000个未过期请求。登录成功签发原本站会话，期限仍由 `AUTH_SESSION_HOURS` 决定；本地账号停用随现有会话查询生效，HR账号沿用现有复核间隔。认证中心停用/退出不会自动撤销本站已建立会话，当前没有全局退出协议。

验收先在新无痕会话打开本站深链接，确认停留原登录页且账号密码登录可用；再在另一新无痕会话登录门户并点击本站，核对免密及角色。需要返回站内指定页面时，在门户入口附加 `?return_to=站内路径`。继续验证未绑定/停用账号、过期或重放回调及认证中心故障后可使用原登录页。本系统退出只清除本站会话并停留登录页，再从门户进入时可能复用认证中心会话；不自动退出门户或其他系统。异常回退先关闭 `SSO_ENABLED` 并重启，保留原账号和绑定配置。

Uvicorn访问日志会移除SSO回调查询参数；反向代理、网关和外部采集同样须避免记录该回调的原始查询字符串。排查只共享错误阶段和脱敏日志，不共享授权码、客户端密钥、令牌或浏览器Cookie。

## 切换 SQL Server

原生部署需安装 Microsoft ODBC Driver 18，并在虚拟环境安装 SQL Server 依赖：

```bash
UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv sync --project backend --locked --extra sqlserver --no-build
```

内置查询映射位于 `backend/app/database/queries/`；只有现场表结构与现有契约不同才按设计核对，不能为首次启动随意替换 SQL。

在“数据库配置 → 数据源”登记 SQL Server 连接，填写真实地址、数据库、只读账号与密码。为 cutting 实例指定该连接的 source_key，并设置 `APP_DATA_SOURCE_MODE=sqlserver`。`source_key` 相同的实例共用客户端，SQL 仍按各自 machine_no 筛选；不同连接不能混用凭据。生产账号只授予必要 SELECT，不使用 sa。

### P1 升级与新增实例

旧部署停止 Web 与 Worker 后，保留原 `.env`、`data/` 和自定义设备目录，执行：

```bash
./.venv/bin/python scripts/migrate_production_lines.py
```

Docker 在停止两个服务后可使用相同程序包执行 `docker compose run --rm --no-deps app python scripts/migrate_production_lines.py`，再同时启动新版本 Web/Worker。工具只读旧外部连接配置，不连接生产库；先备份原文件及有效进程连接，再把统一配置原子写入 data/settings.env。备份目录位于 `data/p1-config-backup-*`（目录0700、含凭据文件0600），不得提交或外传。重复执行不重复创建实例，不覆盖已有统一配置或其他数据源。配置无效明确失败；缺少统一配置的新程序拒绝启动。

当前程序只支持PostgreSQL，旧SQLite状态库升级/导入栈已移除。旧部署必须使用保留的历史版本先完成迁移；当前配置转换工具发现`data/metadata.db`会拒绝操作，不读取或删除历史库，不通过删除文件绕过检查。PG结构、备份与回退见[状态库说明](PostgreSQL状态库迁移.md)。

新安装使用 .env.example 的显式演示配置，实例示例见 `backend/app/configuration/production_lines.example.json`。实例目录结构为 `{schema_version: 2, default_line_id, lines: [...]}`；配置中的默认产线是明确选择，不是服务端请求缺失 line_id 时的回退。

- 新切割线：唯一 id/name/type=cutting/source_key/enabled，独立 device_id、实际 machine_no、原生产分组 production_line_id、alarm.start_at；energy 按现场仪表绑定，没有仪表填 null。物理机床和别名必须全局唯一，防止历史机床范围重叠。
- 新焊接线：唯一 id/name/type=welding/source_key/enabled/timezone；共用 MySQL 时，各实例必须填写互不重叠的 device_nos，独立数据库可留空。
- 在管理员会话中向 `PUT /api/v1/production-lines` 提交完整目录，或按字面更新 settings.env 的 `PRODUCTION_LINES_JSON`。新增同类型实例不改公共 Runtime、Worker、API 或页面代码。
- 先登记连接再引用；保存校验引擎、启用状态及范围。已有 ID、物理设备和机床归属不可重命名/删除；停用实例停止新查询和调度，仍可查看/下载历史切割报表及告警报告。
- 来源变更重建受影响实例；旧请求继续使用原引用，旧队列任务携带来源身份，不能更新新来源快照。三个后台角色在新操作读取同一配置；检查配置诊断的各自独立心跳。

网页原连接表单编辑的是当前所选实例绑定的数据源，密码留空保留锁内最近值。一个来源可被多实例引用，修改它会影响所有引用实例；单独停用产线不会停用共享连接。来源仍有引用时不能删除或改引擎，启用业务不可绑定停用来源。单源的 pool_size/connect_timeout/query_timeout/legacy_tls 等选项统一在 Registry 中管理。连接测试仅执行 SELECT 1，不保存或扩大查询能力。

## HR 与 PDM 独立连接

HR 和 PDM 也使用 Registry。分别设置 `WORKER_SOURCE_KEY`、`FILE_SOURCE_KEY` 指向已登记 SQL Server 来源；魔盒 SYS_CONFIG 的只读来源由 `DISPATCH_SOURCE_KEY` 指定。旧部署的整套专用连接或原显式生产回退由迁移工具转换成这些绑定，运行时没有连接字段继承。启用开关继续为 `WORKER_DATABASE_AUTH_ENABLED` 与 `FILE_DATABASE_ENABLED`；工人可用值和会话复核规则不变。

HR 仅校验集团工号、密码、人员完整性及“可用”字段，不校验 `_Locked`。旧 `WORKER_DATABASE_UNLOCKED_VALUE` 不再读取；“可用”值必须核对现场数据。普通读取按既有缓存复核，写操作强制复核；数据库故障拒绝应复核请求，但不删除仍有效的会话。本地管理员不依赖 HR。Session 查询与高成本鉴权隔离见 [系统架构](../project/architecture.md)。

PDM 关联为 `PDM_DesignDocumentInfo.ID = PDM_DocumentFileInfo.DocumentID`，严格匹配版本；`FilePath` 用作 FO 接口相对路径。迁移工具保留原 HR/PDM 超时；连接后续只由绑定来源的 connect_timeout/query_timeout 配置，不再运行时回退生产连接。

```text
LLM_ENABLED=true
```

管理员可在“自动化”页面配置每日、每周或每月的报表任务。系统会自动生成报表、发送 HTML 附件，失败时按指数退避策略重试，并持久保存每次发送结果。

在 `.env` 配置 SMTP：

```text
AUTOMATION_ENABLED=true
AUTOMATION_SCAN_SECONDS=15
EMAIL_RETRY_BASE_SECONDS=60
SMTP_ENABLED=true
SMTP_HOST=smtp.example.com
SMTP_PORT=587
```

## 启用智能告警

智能告警从生产库 `dbo.alarm_info` 只读采集，按统一目录中各切割实例的机号及起点独立监控。后台每五分钟检查一次，但只有发现新的告警问题时才调用大模型并立即生成实体
PDF；同一问题持续未解除时只更新事件状态，不重复生成。问题解除后十分钟内复发视为抖动，
仍归入原事件；超过该窗口再次出现才生成新报告。系统只采集配置起始时间及之后的
`START_TIME`，首次启用该口径时自动从起点补录，后续按 `ALARM_INFO_ID` 游标增量读取。

在 `.env` 配置：

```text
ALARM_MONITOR_ENABLED=true
ALARM_MONITOR_INTERVAL_SECONDS=300
# 设备范围与起点统一取 PRODUCTION_LINES_JSON；旧同名环境变量不再读取。
ALARM_REOPEN_DEBOUNCE_MINUTES=10
ALARM_MONITOR_BATCH_SIZE=500
```

告警指纹优先由设备名、告警类型、编码和类别组成；没有告警编码时才使用规范化描述，且不包含开始、结束或持续时间。
事件状态、同步游标及报告记录保存在 `data/metadata.db`，因此服务重启不会造成重复报告。
起始时间首次变化时，服务会自动重置游标并按新口径补录；起始日前的本地旧事件仍保留审计，
但不会进入页面列表、统计或新报告。需要人工重新同步当前起始日时，先停服务，在服务器项目目录运行
`python scripts/prepare_alarm_monitor.py` 检查配置，再运行
`python scripts/prepare_alarm_monitor.py --apply`，确认成功后启动服务。
管理员可从顶部“告警”页面查看事件、预览 HTML，并下载实体 PDF。大模型不可用时不生成
规则分析报告；生成失败会保留告警事件与失败状态，后续扫描可重试。

## 通用动态数据源（P13）

“其他数据源”使用 `DATABASE_SOURCES_JSON` 保存至 `data/settings.env`，沿用保存锁、空密码保留、0600 原子替换及失败保留旧快照。此 JSON 含敏感连接信息，不提交仓库、不复制进示例、不在日志或诊断中展示。

管理员测试只执行固定只读 `SELECT 1`；旧生产/HR/PDM/焊接配置与其生效边界保留。连接登记不自动创建产线或授予 SQL 工作台权限；新业务须显式登记数据源绑定。接入步骤统一见 [README 的 P13 说明](../../README.md#通用外部数据源p13)，不另建一套连接流程。
