## 来源优先级与生效诊断

统一优先级保持为 `data/settings.env > 进程环境变量 > 项目 .env > 程序默认值`。管理页面只是写入 `data/settings.env` 的入口，不存在第四份存储。项目 `.env` 使用原有变量展开规则（进程环境优先）；`settings.env` 的值按字面读取，不展开 `${...}`。保留 `PYTHON_DOTENV_DISABLED` 的启动禁用行为。

产线实例、物理机号、范围、仪表及告警起点只取 `PRODUCTION_LINES_JSON`；SQL Server/MySQL 连接只取 `DATABASE_SOURCES_JSON`。实例通过 `source_key` 绑定连接。旧 `DEVICE_CONFIG_PATH/devices.json`、`SQLSERVER_*`、`WORKER_SQLSERVER_*`、`FILE_SQLSERVER_*`、`WELD_*` 只由一次性迁移工具读取，正式应用不会回退读取它们。
- 自动化与 SMTP：管理保存后 Web 原子发布运行快照，Worker 按文件版本在下一轮操作加载；在途操作保持原快照。无效文件或参数保留上次可用热配置并显示异常。
- 数据库页全部配置：统一产线目录、全部数据源参数、生产数据模式及 HR/文件库开关保存到 `data/settings.env` 后，Web 新请求和 Worker 下一次操作自动加载；在途查询继续使用原连接。参数不完整或文件无效保留上次快照，诊断读取本身不触发更新。
- 模型、能管、文件服务、告警/保留策略及其他启动参数：重启 Web、Worker 生效；产线目录及单源连接池/超时已在 P1 中纳入热加载。
- Docker 宿主机 `.env` 变更：执行 `docker compose up -d --force-recreate app worker`；源码更新需加 `--build`。`restart` 不会刷新已有容器的环境。先检查 `data/settings.env` 是否覆盖同名参数，不删除配置或数据卷。

管理员打开“系统设置 → 配置诊断”（`GET /api/v1/configuration/diagnostics`）默认只展示异常配置，可按分类和名称筛选并分页，分别查看 Web/Worker 当前快照、来源、已保存目标、加载批次和热修订。`PRODUCTION_LINES_JSON`、`DATABASE_SOURCES_JSON` 及显式绑定键参与真实值比较，不再展示旧连接继承链。密码、账号、密钥、Token、Cookie、URL 等只返回已配置/未配置；不返回明文或内部逐项比较指纹。

“已生效”表示实际快照与该进程环境下的保存目标一致；冷配置差异显示“待重启”，无效参数、热配置未加载或 Web/Worker 值不同显示“配置异常”。Worker 使用独立心跳，缺失、停止、过期或旧版本未上报时显示未知/异常，不借用 Web 快照。界面版本号标识加载批次，一致性通过实际值逐项比较（包含凭据变化），不能比较脱敏文字或仅看版本号。

诊断接口只读，不触发热加载、重连数据库或后台操作，也不验证外部服务连通性。宿主机尚未注入容器的新 `.env` 不可从容器内获知；先重建两个容器，再用诊断页核对来源、两进程状态和覆盖项。诊断异常不会阻断登录或普通报表查询。

现行保留默认值为报告365天、分析90天、告警发生后30天且已解除、非活动派发365天、审计730天、下载实体7天；对应天数0关闭该类清理。具体边界见下方“数据保留”。

## 切换 SQL Server

原生部署需安装 Microsoft ODBC Driver 18，并在虚拟环境安装 SQL Server 依赖：

```bash
UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv sync --project backend --locked --extra sqlserver --no-build
```

内置查询映射位于 `backend/app/database/queries/`；只有现场表结构与现有契约不同才按设计核对，不能为首次启动随意替换 SQL。

在“数据库配置 → 数据源”登记 SQL Server 连接，填写真实地址、数据库、只读账号与密码。为 cutting 实例指定该连接的 source_key，并设置 `APP_DATA_SOURCE_MODE=sqlserver`。`source_key` 相同的实例共用客户端，SQL 仍按各自 machine_no 筛选；不同连接不能混用凭据。生产账号只授予必要 SELECT，不使用 sa。

### P1 升级与新增实例

旧部署停止 Web 与 Worker 后，保留原 `.env`、`data/` 和自定义设备目录，执行：

```bash
./.venv/bin/python scripts/migrate_production_lines.py
```

Docker 在停止两个服务后可使用相同程序包执行 `docker compose run --rm --no-deps app python scripts/migrate_production_lines.py`，再同时启动新版本 Web/Worker。工具只读旧外部连接配置，不连接生产库；先备份原文件及有效进程连接，再把统一配置原子写入 data/settings.env。备份目录位于 `data/p1-config-backup-*`（目录0700、含凭据文件0600），不得提交或外传。重复执行不重复创建实例，不覆盖已有统一配置或其他数据源。配置无效明确失败；缺少统一配置的新程序拒绝启动。

首次启动由编号迁移机制备份应用 SQLite，执行015告警来源隔离，并根据明确目录迁移旧事件、归并指纹及采集游标。原最新分析与版本同时绑定至升级来源；incident/report/analysis/确认/审计身份不变，不修改外部数据库。保留配置和数据库备份；回退旧程序须停两个进程并恢复同批次备份，不能让旧版本写新的告警事件结构。

新安装使用 .env.example 的显式演示配置，实例示例见 `backend/app/configuration/production_lines.example.json`。实例目录结构为 `{schema_version: 2, default_line_id, lines: [...]}`；配置中的默认产线是明确选择，不是服务端请求缺失 line_id 时的回退。

- 新切割线：唯一 id/name/type=cutting/source_key/enabled，独立 device_id、实际 machine_no、原生产分组 production_line_id、alarm.start_at；energy 按现场仪表绑定，没有仪表填 null。物理机床和别名必须全局唯一，防止历史机床范围重叠。
- 新焊接线：唯一 id/name/type=welding/source_key/enabled/timezone；共用 MySQL 时，各实例必须填写互不重叠的 device_nos，独立数据库可留空。
- 在管理员会话中向 `PUT /api/v1/production-lines` 提交完整目录，或按字面更新 settings.env 的 `PRODUCTION_LINES_JSON`。新增同类型实例不改公共 Runtime、Worker、API 或页面代码。
- 先登记连接再引用；保存校验引擎、启用状态及范围。已有 ID、物理设备和机床归属不可重命名/删除；停用实例停止新查询和调度，仍可查看/下载历史切割报表及告警报告。
- 来源变更重建受影响实例；旧请求继续使用原引用，旧队列任务携带来源身份，不能更新新来源快照。Worker 在新操作读取同一配置；检查配置诊断的独立 Worker 心跳。

网页原连接表单编辑的是当前所选实例绑定的数据源，密码留空保留锁内最近值。一个来源可被多实例引用，修改它会影响所有引用实例；单独停用产线不会停用共享连接。来源仍有引用时不能删除或改引擎，启用业务不可绑定停用来源。单源的 pool_size/connect_timeout/query_timeout/legacy_tls 等选项统一在 Registry 中管理。连接测试仅执行 SELECT 1，不保存或扩大查询能力。

### 保留的 SQL 工作台接口

当前数据库页面已移除 SQL 工作台入口，后端接口保留。SQL Server 模式的执行功能默认关闭；完成管理员访问控制和 HTTPS 部署后，在 `.env` 配置：

```text
SQL_WORKBENCH_ENABLED=true
SQL_WORKBENCH_ADMIN_TOKEN=请使用高强度随机令牌
SQL_WORKBENCH_MAX_ROWS=200
```

同时必须确保SQL Server业务账号只有必要对象的`SELECT`权限。修改配置后需重启 Web 和 Worker。

## HR 与 PDM 独立连接

HR 和 PDM 也使用 Registry。分别设置 `WORKER_SOURCE_KEY`、`FILE_SOURCE_KEY` 指向已登记 SQL Server 来源；魔盒 SYS_CONFIG 的只读来源由 `DISPATCH_SOURCE_KEY` 指定。旧部署的整套专用连接或原显式生产回退由迁移工具转换成这些绑定，运行时没有连接字段继承。启用开关继续为 `WORKER_DATABASE_AUTH_ENABLED` 与 `FILE_DATABASE_ENABLED`；工人可用值和会话复核规则不变。

HR 仅校验公司工号、密码、人员完整性及“可用”字段，不校验 `_Locked`。旧 `WORKER_DATABASE_UNLOCKED_VALUE` 不再读取；“可用”值必须核对现场数据。普通读取按既有缓存复核，写操作强制复核；数据库故障拒绝应复核请求，但不删除仍有效的会话。本地管理员不依赖 HR。Session 查询与高成本鉴权隔离见 [系统架构](../project/architecture.md)。

PDM 关联为 `PDM_DesignDocumentInfo.ID = PDM_DocumentFileInfo.DocumentID`，严格匹配版本；`FilePath` 用作 FO 接口相对路径。迁移工具保留原 HR/PDM 超时；连接后续只由绑定来源的 connect_timeout/query_timeout 配置，不再运行时回退生产连接。

## 启用 LLM

在 `.env` 配置：

```text
LLM_ENABLED=true
LLM_API_KEY=...
LLM_BASE_URL=https://模型服务地址/v1
LLM_MODEL=模型名称
```

`LLM_ENABLED=false` 或模型未配置时，智能分析明确显示不可用，不生成模拟分析。启用并配置服务后需重启 Web 和 Worker；模型失败时保留失败状态或可用的历史分析，不阻断报表业务数据展示。默认并发10、响应时限180秒、容量排队120秒，部署中的显式值继续优先。

## 启用报表自动化

管理员可在“自动化”页面配置每日、每周或每月的报表任务。系统会自动生成报表、发送 HTML 附件，失败时按指数退避策略重试，并持久保存每次发送结果。

在 `.env` 配置 SMTP：

```text
AUTOMATION_ENABLED=true
AUTOMATION_SCAN_SECONDS=15
EMAIL_RETRY_BASE_SECONDS=60
SMTP_ENABLED=true
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=report@example.com
SMTP_PASSWORD=...
SMTP_FROM_EMAIL=report@example.com
SMTP_FROM_NAME=切割生产智能产报系统
SMTP_USE_TLS=true
SMTP_USE_SSL=false
```

587 端口通常使用 `SMTP_USE_TLS=true`；465 端口通常使用 `SMTP_USE_SSL=true` 并将 TLS 设为 `false`。修改 `.env` 后需重启 Web 和 Worker（Docker 需重建两个容器）；从管理页保存的自动化/SMTP 配置写入 `data/settings.env`，Web 发布新快照，Worker 在下一轮操作加载，已开始发送的邮件保留旧快照。SMTP 未配置时定时任务仍可保存，但发送会按规则重试并在发送记录中显示失败原因。

## 启用智能告警

智能告警从生产库 `dbo.alarm_info` 只读采集，按统一目录中各切割实例的机号及起点独立监控。后台每五分钟检查一次，但只有发现新的告警问题时才调用大模型并立即生成实体
PDF；同一问题持续未解除时只更新事件状态，不重复生成。问题解除后十分钟内复发视为抖动，
仍归入原事件；超过该窗口再次出现才生成新报告。系统只采集配置起始时间及之后的
`START_TIME`，首次启用该口径时自动从起点补录，后续按 `ALARM_INFO_ID` 游标增量读取。

在 `.env` 配置：

```text
ALARM_MONITOR_ENABLED=true
ALARM_MONITOR_INTERVAL_SECONDS=300
# 设备范围与起点统一取 PRODUCTION_LINES_JSON；旧同名环境变量不再读取。
ALARM_REOPEN_DEBOUNCE_MINUTES=10
ALARM_MONITOR_BATCH_SIZE=500
```

告警指纹优先由设备名、告警类型、编码和类别组成；没有告警编码时才使用规范化描述，且不包含开始、结束或持续时间。
事件状态、同步游标及报告记录保存在 `data/metadata.db`，因此服务重启不会造成重复报告。
起始时间首次变化时，服务会自动重置游标并按新口径补录；起始日前的本地旧事件仍保留审计，
但不会进入页面列表、统计或新报告。需要人工重新同步当前起始日时，先停服务，在服务器项目目录运行
`python scripts/prepare_alarm_monitor.py` 检查配置，再运行
`python scripts/prepare_alarm_monitor.py --apply`，确认成功后启动服务。
管理员可从顶部“告警”页面查看事件、预览 HTML，并下载实体 PDF。大模型不可用时不生成
规则分析报告；生成失败会保留告警事件与失败状态，后续扫描可重试。

## 文件服务与魔盒

```env
FILE_DATABASE_ENABLED=true
FILE_SOURCE_MODE=http
FILE_HTTP_BASE_URL=http://10.147.0.17:8800
FILE_HTTP_AUTHORIZATION=
FILE_HTTP_COOKIE=
FILE_DOWNLOAD_TIMEOUT_SECONDS=60
FILE_DOWNLOAD_MAX_BYTES=52428800
FILE_DOWNLOAD_RETENTION_DAYS=7
MAGIC_BOX_ENABLED=false
MAGIC_BOX_TIMEOUT_SECONDS=60
MAGIC_BOX_OPERATION_TIMEOUT_SECONDS=180
MAGIC_BOX_CONFIG_CACHE_SECONDS=60
```

文件来源支持 `disabled`（默认）、`http`、`local`、`mock`；`local` 需配置 `FILE_SOURCE_LOCAL_ROOT`，`mock` 仅用于显式联调。真实 HTTP 下载需真实 PDM，模拟数据不得推送真实魔盒。文件服务自己的认证头和 Cookie 留在后端，不复用能管授权码；无认证需求可留空。单文件默认50MiB，成功实体默认保留7天，`0`关闭实体清理。

FO 使用 `GET /FOWebApi/api/FO/FilePreView`，参数为 `filepath` 和 `contentType=application/octet-stream`。文件落在 `data/cutting-downloads/<下载ID>/`，Docker 对应 `/app/data/cutting-downloads`。魔盒地址、Token、Secret和机床IP从生产库 `dbo.SYS_CONFIG` 白名单读取，默认不启用；管理员确认后执行，结果未知时先核对，不能盲目重试。操作流程见 [功能与接口参考](../project/功能与接口参考.md)。

| `DISPATCH_RETENTION_DAYS` | 365 | 非活动派发及相应下载记录 |
| `AUDIT_RETENTION_DAYS` | 730 | 确认及权限审计 |
| `FILE_DOWNLOAD_RETENTION_DAYS` | 7 | 成功下载实体，独立于记录保留期 |

对应天数设为0只关闭该类清理。`RETENTION_CLEANUP_INTERVAL_HOURS=24`、`RETENTION_CLEANUP_BATCH_SIZE=500`；活动报告、待发送邮件、未解除告警、进行中派发和未知结果不进入普通清理。报告文件删除失败进入SQLite重试队列；策略修改后重启两个进程。

## PDF 运行环境

Docker 镜像包含 Chromium 和中文字体。原生部署使用运行服务的同一账号安装依赖与浏览器：

```bash
UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv sync --project backend --locked --no-build
./.venv/bin/python -m playwright install chromium
```

Linux 使用 `playwright install --with-deps chromium` 并安装中文字体，例如 Debian/Ubuntu 的 `fonts-noto-cjk`。离线部署需准备与 Playwright 版本匹配的浏览器，可使用 `PLAYWRIGHT_BROWSERS_PATH`。HTML 导出不依赖 Chromium，PDF 失败可在历史列表重试。

## 上线前核对

确认生产 SQL/HR/PDM 只读账号、设备任务键与日期口径、仪表归属及单位、HTTPS和会话策略、数据保留期限，以及生产数据是否允许发送到目标模型服务。先备份再按 [多设备迁移](../project/multi-device-isolation.md) 和 [双进程升级说明](WEB_WORKER进程隔离升级说明.md) 执行，不能直接覆盖旧库或清空数据卷。


## 通用动态数据源（P13）

“其他数据源”使用 `DATABASE_SOURCES_JSON` 保存至 `data/settings.env`，沿用保存锁、空密码保留、0600 原子替换及失败保留旧快照。此 JSON 含敏感连接信息，不提交仓库、不复制进示例、不在日志或诊断中展示。

管理员测试只执行固定只读 `SELECT 1`；旧生产/HR/PDM/焊接配置与其生效边界保留。连接登记不自动创建产线或授予 SQL 工作台权限；新业务须显式登记数据源绑定。接入步骤统一见 [README 的 P13 说明](../../README.md#通用外部数据源p13)，不另建一套连接流程。
