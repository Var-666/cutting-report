# 切割生产智能产报系统概要设计说明书

**文档版本：** V1.0  
**设计日期：** 2026-08-18  
**对应需求：** 《切割生产智能产报系统需求说明书 V1.0》  
**系统形态：** Vue 3 前端 + Python/FastAPI 后端 + SQL Server + 单文件 HTML 报告

---

## 1. 设计目标

本设计用于将需求说明转化为可实施的软件结构、接口契约和运行流程，指导后续详细设计、编码、测试和部署。

V1 设计重点如下：

1. Vue 3 提供统一的查询、生成状态和历史报告操作界面；
2. FastAPI 统一承担参数校验、任务调度、SQL 查询、统计计算、LLM 调用和报告生成；
3. SQL Server 只作为生产事实数据源，系统使用只读账号访问；
4. 所有关键数值由 SQL/Python 确定性计算，LLM 不参与数值运算；
5. 最终报告为真正可复制、可离线打开的单文件 HTML；
6. 报告生成失败可追踪，LLM 失败不影响基础报告交付；
7. 设计保持简单，适用于 Windows 内网单机部署，并为后续扩展预留边界。

## 2. 设计范围

### 2.1 V1 包含

- 日期、工程号、船号查询；
- 车间明细、汇总基础数据和设备数据查询；
- 数据标准化、质量检查和指标计算；
- 可配置的基础异常/关注项识别；
- ECharts 图表数据生成；
- LLM 结构化生产分析及失败报错；
- 单文件 HTML 报告生成；
- 报告元数据、任务状态和历史列表管理；
- 报告在线打开、下载和打印；
- 日志、安全、测试和 Windows 内网部署。

### 2.2 V1 不包含

- 通用报表设计器；
- 任意 SQL 执行；
- 多级审批；
- 复杂角色权限；
- 实时设备监控；
- WebSocket；
- 分布式任务队列；
- 多节点高可用；
- 自动邮件或企业微信推送。

## 3. 关键设计决策

### 3.1 前后端分离，但采用同源部署

- 开发阶段：Vue Vite 开发服务器与 FastAPI 分开运行；
- 生产阶段：Vue 执行 `vite build`，构建结果由 FastAPI 或同机反向代理提供；
- 浏览器只访问一个内网地址，避免复杂 CORS 配置；
- Vue 只负责系统操作界面，不负责生成最终归档报告。

### 3.2 报告由后端生成

最终 HTML 由 Jinja2 渲染，内容包括：

- 内嵌 CSS；
- 内嵌报告数据；
- 内嵌 ECharts JavaScript；
- 内嵌图表初始化代码；
- 生产明细、设备明细和 AI 分析文本。

报告不得依赖：

- Vue 开发服务器；
- Vue 构建目录；
- CDN；
- 临时 URL；
- 外部字体或外部图片。

### 3.3 V1 使用本地 SQLite 管理系统元数据

SQL Server 仍是生产数据的唯一事实来源；SQLite 只保存本系统自己的数据：

- 报告生成任务；
- 报告文件元数据；
- 生成状态与错误摘要；
- AI 调用状态；
- 文件大小与校验值。

这样可以避免仅扫描目录造成的筛选条件丢失、文件名冲突和状态不可追踪问题。

### 3.4 报告采用异步任务加轮询

报告生成可能包含慢 SQL 和 LLM 调用，因此创建报告后先返回任务标识，Vue 定时轮询状态。

V1 不引入 Redis/Celery，使用受控的本地任务执行器：

- SQLite 持久化任务；
- 后端工作线程读取待执行任务；
- 默认同时生成 1 份报告；
- 服务重启后恢复 `pending` 任务，并将遗留 `running` 任务重新置为可执行状态；
- 后续需要多机部署时再替换为独立任务队列。

### 3.5 统计与展示分离

- 数据访问层返回标准化记录；
- 统计服务生成唯一可信的 `SummaryMetrics`；
- 图表、AI 和报告模板只能读取该对象，不得各自重复计算；
- 报告中展示的统计值和传给 LLM 的统计值来自同一份数据。

## 5. 系统模块设计

### 5.1 Vue 前端

| 模块 | 职责 |
|---|---|
| 查询表单 | 日期、工程号、船号输入和校验 |
| 生成状态 | 展示排队、查询、统计、AI、渲染等状态 |
| 报告结果 | 打开、下载、打印入口 |
| 历史报告 | 查询、筛选、分页和操作历史报告 |
| API Client | 封装请求、超时和统一错误处理 |

V1 不强制引入 Pinia。页面状态较少时优先使用 Vue Composition API；出现跨页面复杂状态后再引入状态库。

### 5.2 FastAPI API 层

负责：

- Pydantic 请求/响应校验；
- API 路由；
- 统一错误码；
- 请求 ID；
- 报告任务创建和查询；
- 报告文件安全打开与下载；
- Vue 生产构建文件托管。

### 5.3 数据访问层

负责：

- SQL Server 连接；
- 固定 SQL 加载；
- 参数化执行；
- 查询超时；
- 字段别名映射；
- 原始类型到领域类型转换；
- 查询耗时和行数记录。

数据访问层不得包含 HTML 或 LLM 逻辑。

### 5.4 统计服务

负责：

- 去重；
- 有效数据筛选；
- SUM、AVG、MIN、MAX；
- 数据质量问题汇总；
- Top N；
- 基础异常/关注项；
- 图表聚合基础数据。

### 5.5 LLM 服务

负责：

- 构造限定输入；
- 调用 OpenAI-Compatible API；
- 超时和有限次数重试；
- 解析结构化 JSON；
- 输出字段校验；
- 失败报错；
- 记录耗时和状态，但不记录 API Key。

### 5.6 报告服务

负责：

- 组装 `ReportData`；
- Jinja2 自动转义渲染；
- ECharts 资源内嵌；
- 临时文件写入；
- 原子重命名；
- SHA-256 校验值计算；
- 报告元数据落库。

## 7. 核心数据设计

### 7.1 查询条件

```text
ReportFilter
├── report_date: date                  必填
├── project_code: string | null        可选
├── ship_no: string | null             可选
└── timezone: Asia/Shanghai            服务端固定
```

字符串进入查询前执行：

- 去除首尾空格；
- 空字符串转换为 `null`；
- 最大长度限制；
- 禁止控制字符；
- 仍然必须通过参数化 SQL 查询，不采用字符串拼接。

### 7.2 汇总基础记录

汇总基础查询必须保证“一条记录代表一个可统计任务”，建议契约如下：

```text

├── project_code: string | null
├── ship_no: string | null
├── segment_name: string | null
├── program_no: string | null
├── cut_length: Decimal | null
├── groove_length: Decimal | null
├── work_time: Decimal | null
├── production_time: datetime | null
└── source_updated_at: datetime | null
```

如果现有数据库没有单一任务 ID，需要由业务确认稳定组合键，不能使用前端序号代替。

## 8. 暂定统计口径

以下规则用于形成可编码的默认设计，最终需由业务和数据库负责人确认：

| 项目 | 暂定规则 |
|---|---|
| 任务数 | 按 `task_id` 去重计数 |
| 汇总数据源 | `SummaryBaseRecord`，不从页面明细反推 |
| 合计 | 对有效非空数值求和；全部为空时显示 0，并产生质量提示 |
| 平均值 | 仅以非空有效记录作为分母 |
| 最大/最小 | 仅从非空有效记录计算 |
| 0 值 | 默认视为有效值，除非字段映射规则另行定义 |
| 负长度/负工时/负能耗 | 视为无效数据，不进入统计，并产生数据质量异常 |
| 重复任务 | 保留一条的规则必须由 SQL 明确，不允许 Python 随机去重 |
| 精度 | 内部使用 Decimal；展示精度由单位配置决定 |
| 空值展示 | `--` |

单位不得由代码猜测。数据库映射交付时必须明确：

- 切割长度单位；
- 坡口长度单位；
- 工时单位；
- 气耗单位；
- 电耗单位。

## 9. 日期和筛选设计

### 9.1 日期范围

服务端使用 `Asia/Shanghai`，推荐按半开区间查询：

```text
[report_date 00:00:00, report_date + 1 day 00:00:00)
```

具体过滤字段必须由数据库负责人确认。若生产按班次跨自然日，应将班次日规则替换上述自然日规则，并写入数据映射文档。

### 9.2 工程号和船号

- 空值表示全部；
- 同时提供时使用 AND 条件；
- 船号下拉项可以受日期和工程号联动过滤；
- 后端不信任下拉框结果，仍执行完整参数校验；
- 不存在的工程号或船号返回空数据，不暴露 SQL 细节。

## 10. 报告生成流程

```text
1. Vue 提交生成请求
2. FastAPI 校验参数并创建 report_id
3. SQLite 写入 pending 任务
4. API 返回 202 Accepted
5. 工作线程领取任务，状态变为 querying
6. 在同一次任务中执行三类 SQL 查询
7. 数据标准化与质量检查
8. 计算唯一 SummaryMetrics
9. 生成 Top N、关注项和 ECharts 配置
10. 构造受限 LLM 输入并调用模型
11. 组装 ReportData
12. Jinja2 渲染临时 HTML
13. 校验并原子保存正式文件
14. SQLite 写入报告元数据
15. 任务状态变为 completed
16. Vue 轮询获得打开和下载地址
```

建议任务状态：

```text
pending
querying
calculating
analyzing
rendering
completed
failed
```

状态用于用户理解进度，不暴露后端堆栈或数据库信息。

## 11. API 设计

统一前缀：`/api/v1`

### 11.1 创建报告任务

**POST `/api/v1/reports`**

请求：

```json
{
  "report_date": "2026-08-18",
  "project_code": null,
  "ship_no": null
}
```

响应：`202 Accepted`

```json
{
  "success": true,
  "data": {
    "report_id": "rpt_20260818_112030_a1b2c3",
    "status": "pending",
    "status_url": "/api/v1/reports/rpt_20260818_112030_a1b2c3/status"
  },
  "request_id": "req_..."
}
```

### 11.2 查询生成状态

**GET `/api/v1/reports/{report_id}/status`**

成功响应：

```json
{
  "success": true,
  "data": {
    "report_id": "rpt_20260818_112030_a1b2c3",
    "status": "completed",
    "stage_message": "报告生成成功",
    "ai_status": "success",
    "view_url": "/reports/rpt_20260818_112030_a1b2c3/view",
    "download_url": "/api/v1/reports/rpt_20260818_112030_a1b2c3/download",
    "generated_at": "2026-08-18T11:20:30+08:00"
  },
  "request_id": "req_..."
}
```

### 11.3 历史报告列表

**GET `/api/v1/reports`**

查询参数：

```text
page=1
page_size=20
report_date=2026-08-18
project_code=A001
ship_no=S001
```

响应包含 `items`、`page`、`page_size` 和 `total`。

### 11.4 在线打开报告

**GET `/reports/{report_id}/view`**

- 根据 `report_id` 从元数据库定位文件；
- 返回 `Content-Type: text/html; charset=utf-8`；
- 不接收任意文件路径或文件名；
- 建议在新浏览器页签打开。

### 11.5 下载报告

**GET `/api/v1/reports/{report_id}/download`**

- 返回 `Content-Disposition: attachment`；
- 下载文件名经过安全编码；
- 文件不存在时返回统一的 `REPORT_FILE_NOT_FOUND`。

### 11.6 筛选选项

```text
GET /api/v1/options/projects?report_date=2026-08-18
GET /api/v1/options/ships?report_date=2026-08-18&project_code=A001
```

数据量过大时支持关键词 `q` 和最多返回条数限制。

### 11.7 统一错误结构

```json
{
  "success": false,
  "error": {
    "code": "DATABASE_QUERY_FAILED",
    "message": "生产数据查询失败，请联系管理员。"
  },
  "request_id": "req_..."
}
```

建议错误码：

| 错误码 | HTTP 状态 | 含义 |
|---|---:|---|
| VALIDATION_ERROR | 422 | 参数不合法 |
| REPORT_NOT_FOUND | 404 | 报告记录不存在 |
| REPORT_FILE_NOT_FOUND | 404 | 元数据存在但文件丢失 |
| DATABASE_UNAVAILABLE | 503 | 数据库连接失败 |
| DATABASE_QUERY_FAILED | 500 | 查询失败 |
| REPORT_RENDER_FAILED | 500 | HTML 渲染失败 |
| REPORT_GENERATION_FAILED | 500 | 其他生成错误 |

LLM 未启用、调用失败或结果校验失败时，报表任务直接失败，不生成降级分析。

## 12. SQLite 元数据设计

### 12.1 `report_jobs`

| 字段 | 类型 | 说明 |
|---|---|---|
| report_id | TEXT PK | 报告及任务唯一标识 |
| status | TEXT | 当前状态 |
| report_date | TEXT | 报告日期 |
| project_code | TEXT NULL | 工程号 |
| ship_no | TEXT NULL | 船号 |

## 13. 文件命名和存储

内部文件路径：

```text
reports/2026/08/rpt_20260818_112030_a1b2c3.html
```

用户下载文件名：

```text
生产日报_2026-08-18_ALL_ALL_112030.html
```

若带筛选条件：

```text
生产日报_2026-08-18_A001_S001_112030.html
```

文件生成步骤：

1. 只在受控临时目录创建临时文件；
2. 使用 UTF-8 写入；
3. 检查文件非空且包含报告结束标记；
4. 计算 SHA-256；
5. 原子移动到正式路径；
6. 成功后再登记元数据。

## 14. 图表设计

### 14.1 V1 图表

1. 切割长度与坡口长度分组柱状图；
2. 切割长度、坡口长度与切割时长双 Y 轴组合图；
3. 设备能耗 Top N 图，仅在有效设备数据存在时显示。

### 14.2 大数据处理

- 超过阈值时按工程号或分段聚合；
- 默认图表 Top N 为 20；
- 图表显示聚合方式和截断提示；
- 图表输入只能来自统计/图表服务，不在模板中临时聚合。

### 14.3 打印

- 打印前调用 ECharts `resize()`；
- 使用 `@media print` 隐藏交互按钮；
- 图表设置固定打印高度；
- 避免图表、指标卡和表格标题跨页断开；
- 明细表允许自然分页，并在打印页重复表头。

## 15. 异常和关注项设计

V1 不进行基于历史训练的自动异常检测，只提供确定性规则：

### 15.1 数据质量异常

- 任务 ID 缺失；
- 关键数值为负数；
- 数值无法转换；
- 同一任务出现重复记录；
- 汇总基础数据与明细任务数量明显不一致。

### 15.2 业务阈值异常

阈值通过配置文件维护，未配置时不启用：

- 单任务工时超过阈值；
- 单任务气耗超过阈值；
- 单任务电耗超过阈值；
- 单位切割长度能耗超过阈值。

### 15.3 Top N 关注项

Top N 只表示“数值排名靠前”，不得自动描述为异常。报告中应区分：

- 数据质量异常；
- 超阈值异常；
- Top N 关注项。

## 16. LLM 设计

### 16.1 输入范围

仅发送：

- 报告日期和筛选条件；
- 单位明确的核心指标；
- 数据质量摘要；
- Top 10 关注项；
- 最多 20 条异常记录；
- 聚合后的设备指标。

默认不发送全部生产明细。

### 16.2 输出契约

要求模型返回 JSON：

```json
{
  "overview": "生产概况",
  "features": "数据特征",
  "alerts": "异常与关注点",
  "suggestions": "生产管理建议"
}
```

后端必须验证四个字段存在且为字符串。模型输出只作为文本处理，不允许作为可信 HTML 直接插入模板。

### 16.3 失败处理

以下情况直接终止智能分析：

- 超时；
- 鉴权失败；
- 模型不可用；
- 返回空值；
- JSON 解析失败；
- 内容校验失败。

报表任务记录为 `failed`，页面显示错误并允许重试；不返回规则分析、模拟分析或空占位结果。

### 16.4 数据安全

生产环境启用 LLM 前必须确认内部生产数据是否允许发送到目标模型服务。若不允许，应使用内网模型或对工程号、船号等字段脱敏。

## 18. 安全设计

### 18.1 数据库

- 使用独立只读账号；
- 仅授权必要视图或表的 SELECT；
- 所有过滤条件参数化；
- 设置连接超时和查询超时；
- 日志不打印完整连接串；
- 不向前端返回 SQL 文本和数据库异常。

### 18.2 Web

- 同源部署，默认不开放跨域；
- Pydantic 校验日期、长度和字符；
- Jinja2 开启自动转义；
- JSON 注入脚本使用安全序列化；
- LLM 输出按纯文本展示；
- 报告访问以 `report_id` 查元数据，不拼接用户文件路径；
- 下载响应增加 `X-Content-Type-Options: nosniff`；
- 生产模式关闭调试页面和详细异常返回。

### 18.3 访问控制

V1 不实现复杂用户权限，但需由部署方在以下方案中确定至少一种：

- 仅允许受控内网网段访问；
- 反向代理基础认证；
- Windows/IIS 集成认证；
- 后续系统登录。

完全匿名开放给整个办公网络属于已知风险，需要项目负责人确认。

## 24. 开发前待确认项

以下项目不阻止概要设计，但会阻止正式的数据查询和统计实现：

| 编号 | 待确认项 | 影响 |
|---|---|---|
| D-01 | SQL Server 表/视图及三类正式 SQL | 无法实现真实查询 |
| D-02 | 稳定任务 ID 或组合唯一键 | 无法可靠统计任务数和去重 |
| D-03 | 日期过滤字段与夜班规则 | 日报数据范围可能错误 |
| D-04 | 长度、工时、气耗、电耗单位 | 报告数值无法正确标注 |
| D-05 | NULL、0、负数业务含义 | 统计口径无法最终冻结 |
| D-06 | 空数据是否生成报告 | 影响 API 和用户流程 |
| D-07 | 业务异常阈值 | V1 只能展示数据质量与 Top N |
| D-08 | 单份报告最大明细条数 | 影响文件大小和打印性能 |
| D-09 | LLM 服务及数据外发许可 | 决定 AI 是否启用/脱敏 |
| D-10 | 内网访问控制方式 | 影响部署与安全验收 |
| D-11 | 报告保留期限和备份方式 | 影响磁盘与运维设计 |

## 25. 设计结论

V1 采用 Vue 3 + FastAPI 的同源 Web 架构，以 SQL Server 为生产事实数据源，以 SQLite 管理本系统任务和报告元数据。报告生成采用可恢复的本地异步任务，统计结果形成唯一可信数据模型，再供 ECharts、LLM 和 Jinja2 使用。

最终交付报告为不依赖 Vue、服务器或外网资源的单文件 HTML。该设计能够满足内网单机部署、长期归档、失败可追踪和后续扩展要求，同时避免在 V1 引入分布式队列、复杂权限和通用 BI 等超出范围的能力。
