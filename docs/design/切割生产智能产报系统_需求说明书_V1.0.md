# 切割生产智能产报系统需求说明书

**文档版本：** V1.0  
**文档日期：** 2026-08-18  
**项目类型：** 内网 Web 生产产报系统  
**最终产物：** 可长期保存、独立打开的 HTML 生产报告

---

## 1. 文档目的

本文档用于明确“切割生产智能产报系统”的业务目标、功能范围、系统边界、数据处理逻辑、页面与报告结构、接口要求、安全要求、性能要求及验收标准，作为后续技术设计、开发、测试、部署和验收的统一依据。

本项目不再以 Dify Workflow 作为最终生产实现，而采用独立 Web 系统完成数据查询、统计计算、图表生成、AI 分析和 HTML 报告生成。

---

## 2. 项目背景

当前生产相关数据存储于 Microsoft SQL Server 中，已具备可用 SQL 查询逻辑，可获取包括但不限于以下信息：

- 工程号
- 船号
- 分段名
- 程序号
- 切割长度
- 坡口长度
- 切割时长
- 气耗
- 电耗
- 其他生产及设备指标

现有产报过程主要依赖人工查询数据库、整理数据、制作 Excel/图表并撰写说明，存在以下问题：

1. 查询和整理过程重复，人工成本较高；
2. 报表统计口径容易因人工处理产生差异；
3. 图表制作过程重复，实时性较差；
4. 报表缺少自动化趋势识别和异常分析；
5. 报告难以统一归档、长期保存和快速复用；
6. 无统一 Web 入口，不利于车间、设备和管理人员使用；
7. 现有临时 HTML/临时 URL 方案不适合作为正式产报系统。

因此，需要建设一个独立的 Web 生产产报系统，实现：

> SQL Server 自动查询 → 后端统计计算 → ECharts 图表 → LLM 智能分析 → Jinja2 生成 HTML → 报告长期保存/打开/下载

---

## 3. 项目目标

### 3.1 总体目标

建设一个基于 SQL Server 的生产数据智能产报系统。用户通过 Web 页面选择查询条件后，系统自动完成：

1. 查询 SQL Server；
2. 生成生产明细数据；
3. 计算核心统计指标；
4. 生成生产可视化图表；
5. 调用大语言模型生成生产分析；
6. 基于统一 HTML 模板生成正式报告；
7. 将报告保存为独立 `.html` 文件；
8. 支持用户在线打开、下载、打印及后续归档。

### 3.2 V1 核心目标

V1 版本必须实现：

- Web 页面可访问；
- 可按日期生成生产报告；
- 支持工程号、船号等筛选条件；
- SQL Server 查询正常；
- 自动计算核心生产指标；
- 生成生产数据明细表；
- 使用 ECharts 生成图表；
- LLM 基于实际统计数据生成分析；
- 自动生成独立 HTML 报告文件；
- 报告可长期保存并重新打开；
- 同一局域网其他电脑可访问系统及已生成报告。

## 5. 系统定位

本系统定位为：

> **基于 SQL Server 的生产数据 Web 产报与智能分析系统。**

系统不是通用 AI Agent，也不是通用 BI 平台。

AI 仅作为生产数据解释与辅助分析模块。

系统职责边界必须保持：

```text
SQL Server
    ↓
事实数据

Python/FastAPI
    ↓
业务逻辑、统计计算、报告生成

ECharts
    ↓
数据可视化

LLM
    ↓
生产数据解释、异常关注、管理建议

HTML
    ↓
最终产报
```

## 6. 总体架构

### 6.1 推荐技术架构

```text
                    ┌─────────────────────┐
                    │      浏览器 Web      │
                    │   Vue 3 + ECharts   │
                    └──────────┬──────────┘
                               │ HTTP
                               ↓
                    ┌─────────────────────┐
                    │       FastAPI       │
                    │     Web 后端服务     │
                    └──────────┬──────────┘
                               │
             ┌─────────────────┼─────────────────┐
             │                 │                 │
             ↓                 ↓                 ↓
      ┌────────────┐    ┌────────────┐    ┌────────────┐
      │ SQL Server │    │ Python统计 │    │   LLM API  │
      │ 生产数据库  │    │ 指标/异常   │    │ 智能分析    │
      └────────────┘    └────────────┘    └────────────┘
             │                 │                 │
             └─────────────────┼─────────────────┘
                               ↓
                      ┌────────────────┐
                      │  ReportData    │
                      │ 统一报告数据模型│
                      └───────┬────────┘
                              ↓
                      ┌────────────────┐
                      │ Jinja2 Template│
                      │ + ECharts      │
                      └───────┬────────┘
                              ↓
                  生产日报_2026-08-18.html
```

### 6.2 推荐技术栈

| 模块 | 推荐技术 |
|---|---|
| 数据库 | Microsoft SQL Server |
| 后端 | Python 3.11+ |
| Web 框架 | FastAPI |
| ASGI Server | Uvicorn |
| SQL Server 驱动 | pyodbc |
| 模板 | Jinja2 |
| 前端 V1 | Vue 3 + Vite + JavaScript |
| 图表 | Apache ECharts |
| AI | OpenAI-Compatible LLM API |
| 配置 | `.env` |
| 日志 | Python logging / structlog |
| 部署 | Windows 内网服务器 |
| 前后端通信 | RESTful API + JSON |

### 6.3 前端与报告的职责边界

- Vue 3 用于系统操作界面，包括查询条件、生成状态、结果反馈和历史报告列表；
- Vue 前端通过 RESTful API 与 FastAPI 后端通信；
- 最终归档报告不由 Vue 页面直接保存，而由 Python/Jinja2 在后端生成；
- 最终报告不得依赖 Vue 开发服务器或 Vue 构建产物才能打开；
- ECharts 可同时用于 Vue 系统页面和最终 HTML 报告，但最终报告所需资源必须随报告内嵌或离线打包。

## 9. 功能需求

#### 9.1 查询参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| report_date | Date | 是 | 报告日期 |
| project_code | String | 否 | 工程号 |

#### 9.2 用户操作

- 船号选择/输入；
- “生成报告”按钮；

#### 9.3 参数规则

- 日期不能为空；
- 工程号为空表示全部；

### FR-02 SQL Server 数据查询

#### 9.4 查询类型

系统至少包含三类查询：

1. 车间生产明细；
2. 领导汇总基础数据；
3. 设备生产/能耗数据。

#### 9.5 SQL 设计原则

- SQL 固定维护；
- 不允许前端提交任意 SQL；
- 查询参数使用参数化；
- 正式环境数据库账号仅赋予 `SELECT` 权限；
- 禁止使用 `sa` 作为正式业务账号。

### FR-06 数据可视化

#### 9.12 图表技术

统一使用 Apache ECharts。

正式 HTML 报告中不使用第三方临时图片 URL 作为主要图表方案。

#### 9.13 图表 1：切割长度与坡口长度

建议类型：**分组柱状图**

- X 轴：任务序号 / 工程 / 分段；
- Y 轴：长度；
- Series 1：切割长度；
- Series 2：坡口长度。

#### 9.14 图表 2：切割时长

建议：

- 折线图；
- 或与长度组合成双 Y 轴图。

推荐组合：

```text
左 Y 轴：
- 切割长度
- 坡口长度

右 Y 轴：
- 切割时长

表现：
长度 → 柱状
时长 → 折线
```

#### 9.15 图表交互

网页打开后支持：

- Tooltip；
- 图例开关；
- 鼠标悬停查看数值；
- 自适应宽度；
- 打印时正常显示。

### FR-07 AI 智能分析

#### 9.16 AI 使用原则

LLM 不负责关键数值计算。

职责：

```text
SQL → 查数据
Python → 算指标
LLM → 解释数据
```

#### 9.17 LLM 输入

建议只输入：

- 核心统计指标；
- 关键明细；
- Top N 数据；
- 异常记录；
- 必要上下文。

不得将数千条原始数据全部发送给模型。

#### 9.18 AI 输出结构

固定输出：

1. 生产概况；
2. 数据特征；
3. 异常与关注点；
4. 生产管理建议。

#### 9.19 AI Prompt 约束

Prompt 必须包含：

- 只能依据提供数据分析；
- 禁止虚构数据；
- 数据不足时明确说明无法判断；
- 数值必须来自后端统计；
- 不得修改统计结果；
- 建议必须与数据相关；
- 输出简洁、可用于正式生产报告。

## 12. 数据处理要求

### 12.1 数据标准化

后端统一处理：

- `NULL`；
- 空字符串；
- Decimal；
- datetime；
- 字段别名；
- 数值精度。

示例：

```json
{
  "project_code": "A001",
  "ship_no": "S001",
  "segment_name": "P01",
  "cut_length": 90158.0,
  "groove_length": 30476.688,
  "work_time": 577.0
}
```

### 12.2 统计逻辑

所有核心统计必须在后端或 SQL 中完成。

禁止让 LLM 计算：

- SUM；
- AVG；
- MAX；
- MIN；
- 同比；
- 环比；
- 生产效率。

## 16. ECharts 集成要求

### 16.1 V1 方案

Vue 系统页面和最终报告均使用 ECharts 生成图表。

Vue 前端通过 npm 管理 ECharts 依赖；最终报告不得直接引用 Vue 前端构建目录中的哈希资源文件。

服务器在线打开报告时可使用本地静态资源：

```html
<script src="/static/js/echarts.min.js"></script>
```

### 16.2 独立 HTML 要求

如果要求 HTML 文件复制到其他电脑后单文件独立打开，则需要：

- 将 ECharts JavaScript 内嵌到报告；
- 或将图表导出为 Base64 图片嵌入 HTML；
- 或打包报告及静态资源目录。

V1 若按本说明书“可独立打开”的目标验收，应采用单文件离线 HTML；不得将该能力推迟到 V1.1。

## 18. 安全需求

### 18.1 数据库

正式账号建议：

```text
report_reader
```

只允许：

```text
SELECT
```

禁止：

```text
INSERT
UPDATE
DELETE
DROP
ALTER
```

### 18.2 SQL 注入

禁止：

```python
sql = f"SELECT * FROM TASK WHERE PROJECT_CODE='{project_code}'"
```

必须参数化：

```python
cursor.execute(
    "SELECT * FROM TASK WHERE PROJECT_CODE = ?",
    project_code
)
```

### 18.3 API Key

LLM API Key 必须：

- 存 `.env`；
- 仅后端访问；
- 不下发给浏览器；
- 不记录到日志。

### 18.4 HTML 安全

如果未来报告包含用户自由输入文本，应进行 HTML Escape，防止 XSS。

报告生成失败，请稍后重试。

## 31. 最终定义

本项目正式定义为：

> **一个基于 Microsoft SQL Server 的生产数据智能产报系统。用户通过 Web 页面选择查询条件，系统自动完成数据库查询、统计计算、数据可视化与 AI 智能分析，并生成可长期保存、可独立打开、可下载和可打印的 HTML 格式生产报告。**

核心技术边界：

```text
数据库负责事实
↓
后端负责业务计算
↓
ECharts负责可视化
↓
LLM负责解释
↓
Jinja2负责报告生成
↓
HTML负责最终交付
```
