# 优化记录

> 更新日期：2026-09-22。只保留会影响后续实现的优化。

## 缓存页面生命周期

- 报表 `KeepAlive` 保留领导、车间和设备三张固定报表页。三页数量有明确上界，避免 `max=2` 时循环切换三页造成持续淘汰和重新挂载。
- 缓存页面失活时取消自动分析、报表查询和轮询，断开表格观察器与全局监听器；重新激活时只恢复一份必要资源。
- 领导和设备页失活时保留已有 ECharts 实例，仅暂停监听与后台任务；重新激活只执行 `resize()`，真正卸载时才 `dispose()`，避免快速切页连续重建 Canvas。
- 前端请求缓存按订阅者计数：仍有登录预加载或其他页面使用时继续复用，最后一个订阅取消后才中止底层 HTTP 请求，过期响应不能写回缓存。
- 文件派发页首次进入只执行一次初始化查询，后续重新激活仅刷新运行状态、机床和派发记录。
- 车间报表分页只更新当前表格页，不再切换智能分析就绪状态；同一日期区间和数据版本的短暂加载或页面失活会保留已有分析结果。

## 端到端请求取消

- 带 `AbortSignal` 的前端 API 请求会携带唯一 `X-Request-ID`；最后一个缓存订阅者离开或请求被替换时，除取消浏览器 `fetch` 外，还会发送一次独立的服务端取消通知。
- 后端按请求标识登记当前 SQL Server 游标，收到取消通知后调用 pyodbc `cursor.cancel()`，使仍在执行的 SQL 尽快停止；取消发生在游标创建前时也会阻止查询启动。
- 取消登记只存在于 HTTP 请求上下文，后台刷新、告警和自动报表工作线程不受影响；缓存复用及迟到结果保护保持不变。
- ODBC 取消属于驱动协作式取消：已完成的查询无需取消，网络中断或驱动不响应时仍可能等待原有查询超时，需在真实 SQL Server 环境继续观察。

## 会话过期恢复

- 登录保护依赖返回 401 时附带 `X-Session-Expired: 1`，前端只对该标记执行全局会话恢复；登录密码、当前管理员密码和 SQL 工作台令牌错误不会误触发退出。
- 收到过期标记后统一清空用户信息、系统信息、预加载和报表缓存，并以 `replace` 跳转登录页；登录成功后返回过期前的页面。
- 多个并发请求同时发现会话过期时共用一次恢复过程，避免重复清理和重复导航。

## 长期页面轮询

- 告警中心的分钟刷新改为串行递归定时：上一轮三个接口全部结束后才安排下一轮，页面卸载时取消底层 HTTP 请求，并用请求序号禁止迟到结果回写。
- 工人车间页的 5 秒刷新同样串行执行；慢查询期间不再叠加新请求，页面失活后不会重新创建定时器。
- 报表生成状态轮询持有独立 `AbortController`；路由任务变化或页面卸载时同时清除定时器和在途请求，避免请求结束后重新“复活”轮询。历史列表翻页也会取消旧页订阅，仅允许最新页结果写回。

## 智能分析请求去重

- 报表数据使用稳定 SHA-256 `data_version`，避免仅依赖日期或局部字段判断缓存。
- 前端在数据版本变化后立即请求，并取消过期响应的展示权。
- 后端按缓存键合并同进程并发请求，减少重复 LLM 调用。
- 缓存匹配要求报表类型、日期和数据版本一致，保留手动强制刷新能力。

## 表格列宽与可读性

- 全局 `v-content-table` 从百分比权重改为“内在宽度 + 剩余宽度均分”，减少短列过宽和长文件名列过窄。
- 列宽根据实际容器宽度以像素生成，最小表格宽度为 560px，容器变化时自动重算。
- 统一居中、单行与省略显示，汇总行不参与内在宽度估算，避免合并单元格扭曲列宽。

## 页面与文件流程

- 文件下载与推送入口合并为文件派发页，直接从 PDM 选择文件，取消用户手工保存文件的前置步骤。
- 批量推送限制为 20 个，后端批量建任务、前端顺序执行，在提高操作效率的同时保留逐项结果。
- 重复派发检查与任务插入使用同一个 `BEGIN IMMEDIATE` 事务，关闭并发请求在“先查、后写”之间同时通过的竞态窗口。
- 推送成功立即回收实体副本，减少服务器存储占用；记录保留至派发保留期，期间仍可追溯。

## 统一数据保留

- 报告、自动化任务、车间任务快照、智能分析版本、告警、派发和审计不再永久增长，按类别使用可配置保留天数每天清理。
- 清理查询只选择已终结记录；待发送邮件、活动告警、运行中报告和活动派发继续保留。
- 报告与告警文件采用持久化删除队列，数据库记录和文件删除失败可恢复；路径解析限制在 `reports/` 下。
- 各类候选主记录单批上限500，避免SQLite参数数量过多并控制单次写事务长度。
