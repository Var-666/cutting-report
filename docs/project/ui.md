# 前端与 UI 约定

> 更新日期：2026-10-24。

## 双列混合侧栏（2026-10-24）

- 管理员默认使用 Soybean `vertical-mix`，深色设备轨 64px、功能栏 180px，功能栏默认固定展开；主题抽屉仍可切换布局、调整尺寸与固定状态。已缓存的布局偏好继续保留，可在主题配置的布局模式中选择“左侧菜单混合模式”。
- 左轨只展示认证设备目录中的真实设备，目前为 20KW、30KW切割机；右栏展示当前设备名称与现有完整业务菜单，子菜单增加主题色边界导引线。不添加未接入的产线、页面或未经接口证实的运行状态。
- 左轨与原顶栏选择器共用 `useDeviceSelection`，保留切换前的日期/筛选、取消旧设备查询及按设备重建页面。混合布局桌面隐藏重复的顶栏设备选择器；窄屏沿用原生垂直抽屉和顶栏设备选择器。
- 顶栏按钮只控制设备轨：展开 64px 显示图标与名称，收起 48px 仅显示图标（悬停可看全名）；180px 功能导航与当前路由层级始终保留。子菜单导引线叠在选中背景上方。标签栏保留标签原宽，溢出时支持横向及纵向滚轮滚动，到达边缘不阻止页面滚动。
- 报表生成表单按实际可用宽度自动换列，下拉、日期和操作按钮统一 40px，按钮与“每页”文字不换行。3项定向回归和当前演示页实测通过，检查 1112px/390px 表单与分页布局；未执行全量测试、生产构建或真实报告生成。
- 7项定向测试通过；本地接口夹具验证 1440px 双列尺寸/设备切换/刷新恢复、深浅色、390px 抽屉/Escape，以及目录加载、失败重试、空状态，无页面脚本错误。未运行全量测试或生产构建，未访问生产系统。

- 精简接入 Soybean Admin v2.3.0，锁定上游提交 `ab40c08992807e303dd8aabb6ec43d7e2334b24f`。原始布局、CSS 和类型保存在 `frontend/src/vendor/soybean-admin/` 并保留 MIT 许可；不引入演示页面、Mock API、Token 登录和整套 monorepo 工具。项目仍使用 npm，构建要求 Node.js ≥20.19，Docker 构建阶段使用 Node 22。
- 管理员采用上游垂直布局、Naive UI 侧栏菜单和面包屑；菜单由既有管理员路由生成，保留全部业务地址、旧地址重定向及管理员/工人守卫。移动端侧栏默认关闭，支持遮罩、Escape 和焦点循环；关闭后的菜单不可获取焦点。主内容独立滚动，切换路由复位至顶部。
- 管理员主菜单顺序为系统首页、生产报表、智能告警中心、文件派发、系统设置；各级菜单都配置业务图标，沿用 Soybean / Naive UI 每级 18px 缩进，保持图标和文字列对齐；侧栏底部不展示数据模式和版本，管理员顶栏不展示用户名与用户图标，继续提供设备切换和带图标的 36px“退出登录”按钮（Naive UI quaternary，与 Soybean 顶栏按钮一致）。
- 父级“系统设置”整行点击进入设置首页并切换子菜单展开/收起，文字链接同样支持点击和键盘操作；子菜单只显示五个具体功能，不重复“系统设置”。报表和设置组不再渲染内容区重复导航。派发页不显示常驻说明条、重复流程解释和宣传文案；仅保留加载/空数据/失败、无法派发的原因、选取范围和参数人工复核等与操作直接相关的提示。
- 设置首页只保留模块入口，不请求或展示大模型累计用量卡，也不显示常驻功能说明。公共管理页状态区样式仅作用于直接包装层，避免覆盖 Naive 标签内部布局。
- Pinia 的 app store 保存侧栏与视口，官方 theme store 管理完整主题状态；现有 Cookie 会话、设备选择、数据缓存、请求取消和后台分析不变。管理员与工人顶栏继续提供设备切换，页面仍按原设备键重建。
- `AppSelect`、`AppDatePicker` 改为 Naive UI 适配组件，保留原有 option 插槽、v-model 原始值类型、`change.target.value`、日期/月 ISO 字符串和原生表单必填校验；停用缓存页面或禁用控件时关闭弹层。原有报表表格、列宽指令与复杂派发业务组件继续使用。
- 登录输入与提交、公共管理页标题、模型用量卡片/统计/按钮/提示接入 Naive UI。首页以 Soybean 主题 Token 为准，默认主色 `#646cff`；既有业务页局部视觉继续沿用下文约定。旧全局样式放入 legacy CSS 层，避免覆盖组件库自身样式。
- 首页及外壳的 `bg-layout`、`bg-container`、主色与状态色类共用主题 RGB 变量；顶栏主题抽屉完整移植 Soybean Admin v2.3.0 官方 20 个组件，保留外观、布局、通用、预设四个 Tab 和全部配置项；主题 store、推荐配色算法、RGB 色阶、主题圆角及四套预设使用同版本源码。生产构建按官方逻辑在刷新/关闭前保存浏览器配置；旧版有效偏好会迁入。NConfigProvider 和首页 ECharts 同步主题，改色不重新查询数据。视图/加载切换复用上游 transition.css 的 fade-slide / fade，减少动态效果时保留最终数值并关闭图表动画。其他业务页面局部视觉按后续任务逐页迁移。
- 构建自动向 `dist/licenses/` 复制上游和运行库许可；源码打包包含 UnoCSS 配置、上游来源和许可，并检查编译产物携带 Soybean 许可。前端专项回归及打包回归通过；隔离演示服务覆盖12个业务页面的1440/390px布局、用量空数据/加载/失败恢复、设备切换刷新、表单校验、导出选择及工人320/390/1440px和权限检查。未调用真实模型、邮件或设备派发，尚未部署内网。

## 设备切换（2026-10-12）

- 管理员与工人布局在顶栏右侧、账号区之前提供设备选择：20KW切割机 / 30KW切割机；复用 AppSelect，36px高半透明蓝底、浅色文字和设备图标，内容区不再单独占一行。目录加载、失败及重试状态明确展示。560px以下管理员顶栏分两行，设备保留在首行右侧、导航菜单在第二行；320–1440px九档宽度及工人顶栏已检查，无重叠或页面溢出。
- 首页、三类标准报表、生成与历史、工人任务和告警按当前设备查询。切换保留已应用日期与筛选，包含最近生产日默认视图；取消旧预加载/查询并按设备重建页面，缓存键包含设备，避免旧响应串入。
- 当前设备编号保存在标签页的 sessionStorage，刷新后继续使用所选设备；无保存选择或设备已移除时使用目录默认设备，不能把Cutter01当作所有部署的默认值。首次加载先校验目录再预加载，跨设备URL以目录默认值决定是否补充device_id。退出或登录失效时清空选择和目录，并使旧目录请求失效；旧请求的成功、失败或finally都不得回写下一会话状态。仅保存编号，不保存业务数据；浏览器禁止存储时仍可在当前页面切换。
- 自动化计划另有固定设备字段，顶部切换不修改计划或正在编辑的配置。设置、账号、模型用量和文件派发继续共享。
- 30KW切割机的电耗与气耗显示“暂未接入”，任务与时长仍展示；导出标注设备名称及能耗未接入状态。

## 通用规范

- 页面使用 Vue 3 Composition API；管理员、工人和功能分组分别由 `layouts/` 管理。
- 项目品牌标识统一使用 `frontend/src/assets/project-logo.png`；管理员导航、工人导航、登录页和浏览器图标共用同一透明资产，并由 Vite 输出到生产环境可托管的 `/assets` 指纹路径，不再使用根路径静态文件或 CSS 临时绘制的三柱标识。
- 通用线性图标使用 `frontend/src/components/AppIcon.vue`，造型参考阿里巴巴 Iconfont 官方图标库，并以本地 SVG 双色渐变呈现；图标按业务语义使用蓝、青、绿、橙、红、紫色系，不依赖在线 CDN，也不使用易受系统字体影响的 Unicode 图形。
- 管理员首页保留六项核心指标、趋势/状态/告警、报告/入口/洞察的数据和入口，容器改为 Soybean 原生 Naive UI 卡片和 UnoCSS 语义类；移除工业蓝背景图、自定义卡片边框/阴影及页面局部动画。各模块独立加载，生产、能耗、告警和报告均显示真实接口数据，窄屏按模块逐级折行。管理员顶栏的高度、Logo、导航和账户尺寸全站共用，切页时不再跳变。
- 管理员和工人内容区统一在顶栏下留 16px，不额外叠加首个组件的顶距。首页主要模块桌面间距 16px、窄屏 12px；领导、设备、车间和工人任务页主要模块间距 10px；管理页主要模块间距 12px；告警页桌面内外层均为 14px、900px 以下均为 12px。网格父容器管理模块间距时，直接子组件不再叠加下边距，包括数据库状态卡、文件派发面板、设置用量卡片和错误提示；控件内部间距仍按各自用途维护。
- 首页快速入口保留三个既有报表地址，只显示主题色图标、报表名称和方向箭头；使用语义主色悬停反馈。
- 页面保留浅灰蓝背景，内容卡片统一白色，模块标题栏使用 `--panel-heading-bg: #f3f7fa`，不再通过全局浅蓝渐变覆盖卡片、快捷入口和洞察内容。横幅与告警监控状态卡沿用各自配色，首页系统运行状态卡按下述约定融合背景。
- 首页欢迎横幅的浅色遮罩保持不透明至横幅宽度的 50%，完整遮住右侧照片在桌面/中屏的左边界，再分段降低透明度，避免色差形成竖直接缝。照片位置、文字、状态卡和横幅尺寸保留；760px 以下沿用整幅背景与浅色遮罩。
- 首页系统运行状态卡使用 92% 不透明的浅蓝白底，减弱边框、分隔线与阴影；正常状态文字与圆点用绿色，异常文字与圆点用橙色，数据库、版本等辅助信息使用蓝灰色。只调整配色，保留位置、尺寸、字号与交互。
- 普通指标图标使用 `AppIcon` 的 `muted` 蓝灰色；电耗、切割时长和涉及工程等指标不使用红橙色装饰。待确认、已确认、告警严重性、涨跌、错误提示继续保留各自状态色，图表系列色保持原样。报表日期、单位、说明、迷你趋势空状态和分析辅助文字使用 `--muted: #526b7c`；字号与布局不因配色调整改变。
- 告警中心沿用首页的蓝青主色、彩色语义图标、圆角卡片和字号层级；概况指标只展示接口可验证的数据，告警事件同时展示生产库告警时间和系统发现时间，并支持按严重、一般、提示筛选；页面依次显示全宽告警事件表、全宽 AI 分析和实体报告，避免分析侧栏撑高表格所在行。AI 分析中的发现与建议在宽屏分为两列，760px 以下按顺序显示；只有一组内容时占满宽度。长分析完整换行，证据记录保留展开交互；表格继续复用内容列宽与内部横向滚动。
- 领导报表沿用首页生产横幅、彩色指标卡和蓝青色内容层级；指标涨跌只使用接口返回的 `comparison_total`，没有对比数据时明确显示“暂无对比”。区间明细与近 12 个月趋势继续维护独立数据状态。
- 设备报表采用“设备横幅内嵌查询栏、五项设备指标、区间能耗、近 12 个月能耗、智能分析”的单页结构；指标仅使用接口真实数据，其中能耗覆盖率按电耗/气耗匹配记录计算，不用缺失字段模拟设备利用率。
- 车间报表采用“生产横幅内嵌查询栏、五项任务指标、任务结构概览、任务筛选表、工人工时汇总、智能分析”的单页结构；概况卡仅展示任务总数、待确认、已确认、涉及工程和确认率，不用缺失字段模拟异常任务或环比。
- 既有生产源记录按业务规则不可变，车间页不提供“更正日报源记录”。正常新增任务补采、工人确认/撤销及管理员确认人更正保持原流程；新增入口和业务流程需用户明确提出。
- 首页字体按桌面可读性分为标题、核心数值、模块标题、正文和辅助信息五级；窄屏不缩小正文来强行容纳导航，而是保留图标并隐藏重复文字标签。
- 首页指标、模块标题只显示中文，使用 NCard、NStatistic/NNumberAnimation、NTag、NButton、NSpin/NEmpty；单位/辅助信息使用 NText depth="3"。删除 admin-home.css 和两个 Home 组件的局部样式，主间距统一 gap-16px。设备工时仍按小时/分钟展示，缺失能耗与 0 保持区别。
- 全局字号使用统一语义标尺：页面主标题 38px（移动端 31px）、页面说明 12px、模块标题 14px、KPI 名称 11px、KPI 数值 22px、表头 10px、表格正文 11px、控件 11px、辅助信息不小于 9px。报表时间与切割时长继承表格正文字体，保留等宽数字对齐；除 SQL 和文件名外不使用等宽字体，不使用 Georgia 等额外装饰字体。
- 告警事件表沿用普通表格字号：表头10px、正文11px，事件名称、告警代码与状态标签继承单元格字号。实体报告列表保留表头13px、正文14px；AI正文14px、模块与分析标题16px、辅助说明12px。设备编号在告警中心（含报告名称、证据和 AI 文案）、首页告警摘要及设备报表范围中按目录显示名称：Cutter01 为“20KW切割机”，Cutter02 为“30KW切割机”；只转换展示文字，保留 API 编号、下载地址和实际文件名。
- 告警事件操作列使用事件分页接口返回的关联报告状态和查看链接，不从最近 50 份报告推断“已归档”；分别展示待生成、生成中、生成失败、查看、报告不存在或报告不可用。报告状态不表示告警已解除；生成失败后的事件仍按原机制解除关联，等待下一轮重试，历史失败记录保留在实体报告列表。
- 首页交互参考 shadcn-vue、Radix Vue、PrimeVue/Sakai 的卡片层级和可访问交互：导航、卡片链接和快捷入口必须提供清晰的悬停、按下及键盘焦点状态；首页仅保留轻量悬停与加载反馈，并响应 `prefers-reduced-motion`。
- 动效仅用于表达层级、状态和操作反馈，不在生产看板使用大幅视差、3D 倾斜或持续干扰读数的装饰动画。
- 报表生成、设置首页、数据库、报表设计、自动化和管理员管理统一使用 `ManagementPageHero` 与 `management-page` 密度系统：生产场景头图承载页面识别和实时状态，工作面板统一 10px 圆角、浅蓝灰表头、紧凑控件与无斑马纹数据行。工人任务页直接复用车间报表结构，不维护重复样式。
- 数据库配置页的生产数据模式仅提供 SQL Server 与演示数据；移除 TASK.xlsx 选项、本地文件状态卡及 SQL 本地兼容提示，顶栏和首页同步移除 Excel 数据源标签。SQL 工作台只在 SQL Server 模式且服务端开关启用时开放执行；演示模式保留语法校验。1440/390/320px及空数据、加载、失败状态已检查。
- 报表自动化页在 1100px 以上将运行/邮件参数与任务编辑并排展示，以下按顺序排列；760px 以下配置分组单列，560px 以下表单字段单列。模块间距统一 12px，概况与标题图标使用蓝灰色，保存/创建使用主按钮。计划/邮件表保留完整列与区域滚动、固定表头，邮件记录最大高度 440px；任务、收件人和长错误信息靠左，错误信息可换行，窄屏提示左右滑动。SMTP 地址字段解释域名/IP 与网页登录网址的区别；加载和失败时不显示虚假零值，配置就绪只表述为参数已配置。
- 登录页使用同一生产场景图、工业蓝青色板和彩色业务图标，以“生产能力说明 + 白色认证面板”双栏呈现；认证、初始化和 HR 登录逻辑不因视觉重构改变。
- UI 可访问性遵循 Web Interface Guidelines：管理员与工人布局提供 Skip Link；异步成功/失败使用 `status`/`alert` 播报；关键弹窗统一使用焦点循环、Escape 关闭和关闭后返回焦点；表单控件提供稳定 `name`、自动填充语义及可访问标签；数据库、报表设计和自动化编辑页离开前提示未保存修改。
- 报表设计器的查询、定义和模板 Tab 使用完整 ARIA Tab 语义，支持左右方向键、Home/End，并将当前 Tab 写入 URL 查询参数以支持刷新和深链恢复。
- 统计报表的页面查询、导出和智能分析使用同一已应用区间，不在子组件中重新推导日期。
- 领导、设备报表的近 12 个月趋势使用独立数据状态；区间查询只更新区间明细、汇总和智能分析，不覆盖第二张近 12 个月图表及表格。
- 领导、设备报表导出 HTML/PDF 时同样保持双周期：第一组明细及智能分析使用已应用查询区间，第二组趋势始终使用页面独立维护的近 12 个月周期，禁止用区间聚合覆盖月度汇总。
- 报表和设置页面只使用左侧菜单导航，不在内容区重复展示路由子导航；报表面板统一使用 10px 圆角和紧凑密度。领导报表为多个根节点，趋势组件根节点的间距使用直接 scoped 选择器，避免仅用需要祖先容器的 deep 规则导致覆盖失效。
- 领导、设备和车间报表的查询区统一使用头图内嵌的 `StandardReportQuery` 组件；日期、图表类型、查询和导出的字号、40px 控件高度（含 Naive 下拉框）、间距、颜色及响应式布局只在组件内维护，页面仅传入状态和事件。
- 三张标准报表的智能分析统一使用 `AnalysisPanel` 组件，并固定为“分析结论、六项核心指标、2×2 多维分析、模型输入数据”结构；组件使用主题容器、边界与主色/状态色，随 Naive UI 深浅色配置同步；页面不再传入独立样式类或覆盖网格列数。
- 三张标准报表的头图信息区统一使用 `report-hero-copy` 两层轨道：英文眉题和 38px 中文标题；移除常驻功能说明、更新时间、快照状态及宣传标语，保留查询、加载、失败和条件未应用等操作反馈。
- 领导、设备报表的图表共用主题主色、成功色、警告色、坐标网格和平滑折线；车间报表在明细表之前展示完整筛选结果的任务时长环图、确认状态比例条与切割长度 Top 5 横向条形图，图表不受当前分页影响，任务与工人明细仍保留表格。Top 5 只纳入有效正长度，缺失数据明确显示空状态。
- 领导和设备报表的固定高度趋势表允许在表格区域内纵向滚动；车间任务表继续使用分页，不增加固定高度内滚动。
- 三张标准报表的导出 HTML/PDF 共用“生产档案蓝图”视觉：深海军蓝报告识别带、连续指标带、浅蓝表头、无斑马纹数据表和四色智能分析区；PDF 使用 A4 横向、重复表头、长表分页及系统名/页码页脚。
- 三张标准报表的指标卡统一使用 `MetricSparkline`：领导卡读取每日汇总，车间卡读取后端按日聚合，设备卡读取任务和能耗记录；无有效数据时明确显示暂无趋势，禁止固定 SVG 装饰折线。
- 中文日期由 `frontend/src/utils/dateDisplay.js` 统一格式化：月份、日期、日期时间不应在页面内各自拼接。
- 时间区间的原始值保留 ISO/`YYYY-MM-DD` 形式用于 API 和排序；格式化仅用于显示。

## 表格

- 应用内页面表格统一添加 `v-content-table`，对应指令位于 `frontend/src/directives/contentTable.js`。
- 列宽先根据当前表头和渲染行计算内在宽度，再将容器剩余宽度平均分配给各列。列宽通过生成的 `colgroup` 同步到表头、正文和汇总行。
- 表头和单元格默认居中、单行显示；超出宽度时使用省略。窄屏溢出只在表格容器内横向滚动。
- 领导、设备和车间三张标准报表的表头统一使用 Naive UI `tableHeaderColor` 与 `textColor1`，通过共享 CSS 变量同步深浅色，不在页面中固定浅色表头。
- 列宽指令通过容器尺寸观察器重算；新增页面不要手工维护第二套百分比列宽。

## 页面交互

### 车间确认

- 更正原因弹窗根据工人撤销、管理员撤销和管理员改派显示对应的常用原因。
- 常用原因是快捷填写，用户仍可输入其他原因；选中项需有清晰激活态。

### 文件派发

- 文件派发使用一套 PDM 项目/目录树和文件表格，不要求先将文件手工保存到系统。初始化时项目目录、派发记录与服务状态并行读取，目录不等待生产库中的魔盒配置检查；状态检查超过30秒或失败时明确提示并提供绕过浏览器缓存的重新检查入口，状态未确认时禁止新派发。首次项目读取被离开页面打断后，返回会重试；已加载的目录和选择继续保留，过期响应/机床状态取消不回写提示。
- 目标机床按已确认的地址映射展示名称：`10.147.1.40` 为“20kW 切割机”，`10.147.1.38` 为“30kW 切割机”。页面及批量确认弹窗的目标机床选择框均展示“中文名称 · IP（在线状态）”；状态说明、派发记录及执行确认提示共用名称，保留在线状态；选择值和派发请求仍使用原始 IP，不按末位数字推断其他地址的功率。
- 页面沿用首页的生产横幅、彩色语义图标、圆角卡片和蓝青主色。桌面工作区首行为“固定目录栏 + 自适应文件区”，派发确认作为下一行横向摘要，避免十列表格、目录树和确认栏互相挤压；文件区有 600px 初始最小高度并决定首行高度，目录栏等高且目录树仅在栏内滚动，窄屏折为单列并取消桌面最小高度。四步流程状态随选择、确认和派发结果变化。
- 文件派发只有一个正式页面，不显示单项目子导航；管理员主导航直接进入派发工作区，旧下载、推送深链仍重定向到该页面。
- 来源文件表支持单文件派发、当前目录查询结果所有分页全选和跨页多选，最多 100 个文件；每个文件保存独立参数，不共用一份可变表单状态。
- 全选不按标准名过滤，路径可用的非标准文件同样可选。表头全选自动读取当前目录、已应用搜索条件下的所有分页，取消全选也作用于全部分页；勾选/半选状态表示该范围实际选中情况，加载失败不提交部分选择，切换目录或搜索条件会清空选择；达到跨页100项上限或版本重复导致选择被拒绝时，立即恢复全选框和单行复选框的真实状态，并提示原因。
- 恰好选满100项时不显示上限提示，桌面和窄屏仅显示选择数量；尝试选择第101项或全选导致超限文件被跳过时，才拒绝额外文件并提示需先取消部分选择。
- 来源文件表在操作时间后显示“派发状态”，按文档和版本读取独立长期摘要中的最近一次派发状态及阶段；明细记录清理后仍保留显示，无匹配摘要时显示“暂无记录”。不受下方记录分页影响，派发或重试结束后刷新当前文件页状态。
- 派发记录使用独立服务端分页，每页 10 条，沿用“上一页—页码/总数—下一页”；翻页失败保留原页，刷新继续读取当前页，空末页回到有效页。
- 派发记录不提供“取消指派”入口：魔盒接口响应不足以确认机床端任务已撤回。仅对服务端标记可执行的任务展示执行/重试，其余操作显示 `--`；后端取消接口暂保留，机床端撤回效果待内网验收。
- 标准文件名接受 `P/S/W/L/Z` 前缀并自动填入材质和厚度；板厚后的 2 位材质代码原样填入，不限制代码内容、不转换为材质牌号。例如 `Z806C080A001.gen` 填 A0、8 mm，`S803C320B001.gen` 填 B0、32 mm。非标准文件不猜测参数，必须手工填写并勾选人工核对确认。
- 同一 PDM 文档一次只能选择一个版本；标准名对应的材质或板厚被人工修改时也必须再次确认。
- 执行前以弹窗列出选中任务及其参数；系统逐项复核版本和路径，再顺序下载、校验、上传和指派。
- 执行后逐项显示成功、失败、重复、任务编号和本地清理警告；失败项可在弹窗核对状态、重试创建或安全重试，PDM 版本/路径过期需刷新清单重选。上传结果未知时不提供盲目重传。

### 智能分析

- `AnalysisPanel` 默认视图在报表就绪后只读取最近一次完成的默认分析，显示原生成时间；每10秒轻量读取已完成结果，后台新结果完成后替换，未完成/失败保留旧结果，数据版本未变也更新新生成内容。无结果时等待后台，不由页面额外调用模型。读取缓存显示“读取中”，按需调用模型显示“分析中”；每300秒源版本检查及手动重新分析保留。自选区间仍按完整数据版本缓存/按需生成；切换设备、日期或默认/自选模式时取消旧请求并清除跨范围内容，较旧结果不覆盖手动生成的新结果。
- 等待、分析中、错误、已缓存和手动重新分析状态要分开呈现；页面只展示大模型分析结果，模型失败时显示错误和重试入口。
- 智能分析继续内嵌在领导、设备和车间报表中，不单独建立分析路由；首页洞察入口进入对应报表。
- 智能分析的核心指标卡只展示复合事实值的首段概览，完整事实值和来源保留在下方“模型输入数据”；结论和分析卡片默认展示完整文字，允许随内容增高和长词换行，不截断正文。
- 智能分析的页面、缓存和导出共用服务端展示用语：将“未标注工程”等内部分类名说明为“工程号未填写”，将“高位生产日”“环比/同比”等改成日常说法；只调整结果文案，不改变原始任务归类和计算。页面展示模型输入数据，不宣称逐句核验模型结论。

### 报表自动化

- 页面依次分为“运行与邮件参数、新建/编辑任务、定时任务、发送记录”。
- SMTP 密码不回显；已配置时使用“留空则保留原密码”占位提示。
- STARTTLS 与 SSL/TLS 互斥；保存成功后必须明确显示“即时生效”，正在执行的邮件按旧配置完成。
- 配置加载失败时不显示可提交的默认表单，仅显示错误和重试入口，防止覆盖有效配置。

- 智能分析在同设备、同查询区间更新时保留上次结果，显示上次生成时间及旧数据提示；更新失败显示错误并保留旧结果。设备、主区间或汇总区间变化即清空，首次无结果仍显示加载状态。此保留仅限当前页面已有结果，不跨刷新恢复旧分析。

- 六种菜单布局复用官方菜单组件；标签栏复用原生 PageTab（三种风格、缓存、中键关闭），水印、面包屑、顶栏语言/菜单搜索和布局尺寸均接入主题状态。路由适配保留业务菜单、系统设置父菜单跳转及设备缓存边界。主题抽屉源码完整性由 source manifest 校验。

- 首页欢迎卡片仅保留标题、欢迎信息和日期时间，移除系统运行状态摘要及数据源状态链接。

- 标准报表的卡片、查询、分析、反馈及日期弹层使用 Soybean RGB 主题变量与 Naive UI `useThemeVars`；共享变量桥接位于 `theme/reportVariables.js`。报表 ECharts 沿用官方 `useEcharts` 的主题切换方式，由 `useReportChartTheme` 监听深浅色及语义色后销毁并重建实例，背景透明；仅重绘现有数据，不触发查询，缓存中的非活动页面在再次激活时绘制。

- 告警、文件派发、生成历史、系统设置及所有管理子页共用主题容器、文字、表头、状态色、输入框与弹层变量；登录与工人确认区的旧全局样式同样使用主题变量。`AppIcon` 的语义色与主题同步，模型用量图复用 `useReportChartTheme`，切换颜色不重复查询并释放旧图表/尺寸观察器。模板设计器的导出预览保留用户配置的印刷配色，编辑区跟随应用主题。本轮仅验收桌面，不调整窄屏布局。

- 固定表头和汇总行的主题底色必须叠在不透明的容器背景上；Naive UI 表头和主色浅底含透明度，不能直接作为粘性单元格的唯一背景。共享遮挡规则放在 `assets/content-tables.css`，同时覆盖领导和设备报表的明细/月度表。

- 模型用量页移除统计说明及历史累计卡片；每日/月表格与趋势图只展示 `call_count > 0` 的周期，保持原查询汇总口径。失败请求、未返回 Token 和实际返回 0 Token 的周期仍展示；全空区间显示简短空状态，不补零行或空图表。
