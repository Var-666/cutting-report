## 访问协议和数据流

`ProductionReportProvider` 提供报表类型、源身份、统计、明细、刷新和刷新计划；业务查询可保留自身类型和指标。切割适配器包装现有领导月报，旧 API 请求和响应不变；其他稳定切割 API 保留。两条产线共用 QueryCache、CacheRevision、Worker 及 Provider 解析接口。领导月报的历史 SQLite 存储保持兼容，不强行搬入新表；新的通用仓储可用于后续切割统计或新增产线。

焊接首页及四类报表统一先读完整页面快照、后台生成。首页用 `dashboard`，其他页面用 `page:daily/jobs/parts/equipment`；键包含日期、规范化筛选、页码、每页数量、排序、源身份及权限范围。设备/机器人/工艺/状态代码0是有效筛选。每份页面快照在同一个MySQL一致性只读事务内生成汇总、图表、当页明细及总数，不把旧统计数量与实时明细混合；只计算当前报表的专属统计，不再要求四类全部完成后才能显示。首页额外包含今日指标及最多10条最近作业，普通页最多100条明细。原 `statistics` 聚合键和处理路径保留用于已有直接内部调用，不再周期预热整套统计包；升级前队列遗留的 `statistics/daily/jobs/parts/equipment` 刷新任务在消费时直接记录跳过并完成，不打开MySQL、不占用源统计锁。其他产线和其他业务任务不受影响。

有效页面快照：L1命中直接返回；否则读取SQLite并验证内容校验和。首页、日统计、设备、作业及工件页面均不打开MySQL连接；明细与统计截止时间一致，页面明确显示来源及截止时间。分页和排序读取各自的快照，绝不拿另一页或另一组筛选的数据充当当前结果。

缺失页面快照：Web只向原持久化队列提交去重刷新，不执行源库查询，也不等待OS锁。返回带 `X-Welding-Error: snapshot_refresh_busy` 的准备状态；前端最多等待180秒并自动重读，期间维持加载状态，切换条件或离开页面立即取消。数据库、权限、网络和容量错误不自动重放。Worker在每线共享OS锁内再次读取SQLite，随后计算并原子保存完整页面。原内部聚合路径仍保留5秒单飞等待及已有降级行为。

过期页面快照：返回尚未淘汰的同查询快照并标记stale，同时提交去重刷新；用户“查询/刷新”同样先返回已有数据，再由Worker重算，不阻塞页面。刷新期间前端每5秒重读一次，最多75次；后台检查不遮住已有指标、不应用未提交草稿、不改写URL，切换产线、筛选及卸载会取消旧检查。页面刷新完成后自动替换，失败保留旧快照。登录预加载覆盖当前焊接页面，与页面共用按产线隔离的短期内存请求缓存；退出及切换产线沿用既有清理机制。

Worker先提交首页最近7天的预热，再提交四类报表今日默认第一页；历史区间、其他筛选、排序及页码在实际查询时按需生成，不扫描所有组合。任务每次执行重新解析当前Provider，源指纹变化的旧任务直接结束；同线同类任务串行，共享OS锁继续防止重复查询。页面任务计算完成时间若已晚于提交时间则复用结果，否则执行刷新，确保显式刷新不会被仍有效的旧数据吞掉。后台模式不自行重新排队。失败保留旧快照，沿用30秒起、最长1小时的退避重试。

公共统计改为一条只读SQL：日期和筛选在 `scoped_jobs` CTE内执行，保留阻止合并的LIMIT，使汇总、按日、设备工位、设备分布及关联核查共享一次源表读取。聚合表达式与原查询共用，保留重复工件、空设备/机器人、异常时间和单位口径；关联归属只对当前有效流水号匹配工件后分组，但仍统计其全部归属，不按项目或工件状态错误缩减所有者数量。设备/工位及分布的上限不变。

工件查询同样先按作业日期和筛选聚合参与流水号，再匹配工件并物化 `scoped_parts`；避免从全部工件逐行探查作业表。项目统计和工件汇总合并为一条查询，分页复用相同范围定义。归属数量在外层项目/状态筛选前计算，重复工件即使分属不同项目仍保持歧义标记；项目图只使用存在有效时间作业的唯一归属工件，工件总数/明细继续保留有区间候选作业但时间无效的记录。每页及总数的查询谓词共用绑定参数，不通过修改开始/结束时间口径或源库结构提速。

页面后台生成时，三表全局MAX(update_date)及完整设备目录按后台刷新间隔共用有界内存采样，至少30秒；源配置切换建立新服务及源键，不能复用旧源样本。业务统计和当页明细仍每次重新读取同一源事务。`meta.source_info_as_of`单独显示源信息采样时间，不把复用的水位标为刚查询；导出及原直接内部统计路径保留现场源信息读取。不新增源表索引、临时业务表或生产DDL。

快照任务日志明确记录任务ID、产线、报表类型、日期范围、开始/结束、完成或失败及耗时；不输出连接凭据或完整筛选。启动期间的历史租约冲突日志不代表当前Worker不可用，应同时检查 `docker compose ps` 和 `python -m app.worker --health` 的当前租约状态及心跳年龄；不删除有效租约。旧任务跳过逻辑需更新Worker代码后重启才生效，已经进入源查询的旧代码任务不会被热改源码打断。

## 配置、新鲜度与资源上限

复用已有配置及诊断来源，不新增配置项或管理入口：

- `REPORT_BACKGROUND_REFRESH_SECONDS`：当前月及近期统计有效期和预热间隔，最小30秒，默认300秒。
- `LEADERSHIP_REPORT_HISTORY_CACHE_SECONDS`：历史区间有效期及原内部聚合快照的降级期限，最小使用值30秒/1秒，默认86400秒。页面快照可以展示尚未淘汰的旧结果，但必须显示过期及截止时间。
- `REPORT_DATA_CACHE_SECONDS`：共享L1有效期；焊接L1最多30秒，筛选统计L2最多30秒。0关闭L1，筛选L2采用最短1秒；原切割缓存参数行为不变。

有效期内不必逐次查询MAX(update_date)。该字段仅保留为辅助源水位展示，不作为可靠CDC。TTL、显式刷新、Worker刷新、源身份与格式版本共同决定有效性。缓存命中元数据明确source=cache/snapshot；现场刚生成标记database。`data_as_of`为源快照计算开始时间，`refreshed_at`为完成时间，页面同时显示源表水位，不能把旧统计伪装成实时数据。

每线焊接L1最多16项、SQLite统计最多128项；写入时清理超过30天的过期缓存。新统计任务全局最多64个未完成任务，复用原256个就绪位，多余快照请求不继续积压。已完成任务按既有30天清理；周期任务复用固定去重行，不逐轮新增记录。每线统计刷新由OS锁串行，数据库连接池大小和Web焊接执行限额保持原值。

MySQL不可用时，所有已存在的页面快照仍可读取，包含当时真实的明细及总数，并明确显示截止时间和过期状态。没有快照时不能伪造零值或空明细。工件焊缝下钻及导出仍读取源库；分析以页面快照校验data_version，保留版本冲突及模型错误处理。确认、修改、派发与本快照无关。

## SQLite变化与回滚

增量创建 `report_snapshots`，不修改或重建旧表。主键为 `(line_id, report_type, period_start, period_end, query_fingerprint, source_fingerprint, snapshot_schema_version)`；其余字段为 `data_version, data_as_of, refreshed_at, expires_at, payload`。查询指纹包含规范化筛选与权限范围，当前焊接报表仅管理员范围。源指纹只在内部存储/队列使用，不回显凭据。data_version列为统计包内容校验和；公开焊接data_version仍按原业务算法生成，不把分页、生成时间或新元数据纳入分析版本。

SQLiteDatabase继续管理WAL、提交回滚和执行租约。外部查询不占SQLite长事务；完整包和有界淘汰在一个短事务提交，旧执行者失去Worker租约后不能提交。启动的现有初始化文件锁保证增量建表幂等。升级前按现有运维流程做SQLite备份，无生产MySQL/SQL Server表结构变更。

回滚应用前先停止Web/Worker，备份SQLite，将新类型的未完成任务置为completed并保留回滚原因，再启动旧版，避免旧Worker误把welding交给devices。仅针对自有队列执行：

```sql
UPDATE background_tasks SET status='completed', owner=NULL,
    last_error='ROLLBACK_CANCELLED'
WHERE kind='report_snapshot_refresh' AND status!='completed';
```

新快照表可保留；旧代码不会读取，不必删除数据库或恢复覆盖旧业务快照。恢复新版后可以重新按需生成统计。
