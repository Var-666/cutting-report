# 前端反馈与浮层交互规范

按用户是否需要决策、结果是否需要持续展示、内容是否需要参照原页面选择组件。按钮使用业务动词，说明操作对象和结果。

| 组件 | 使用场景 | 示例 |
| --- | --- | --- |
| Tooltip / Popover | 指标释义、按钮说明、日期选择等短交互。图标触发器有可访问名称，必要信息支持键盘和触屏 | 指标口径、报表区间选择 |
| NMessage | 一次性成功回执，通常显示 3 秒。同一次成功回执只展示一次 | 数据源配置已保存、流水号已复制、报表任务已提交 |
| NAlert / ReportFeedback | 应持续可见的状态，在相关表单或结果附近显示。可恢复的错误提供重试入口 | 数据不完整、连接或查询失败、邮件待核对 |
| NPopconfirm | 对象和后果明确的局部确认。异步提交期间禁用确认动作，失败信息留在相关模块 | 删除单个监控，保留故障历史 |
| Modal / useConfirm | 重要确认和集中核对，保留标题、对象、影响和明确动作 | 授予或撤销管理员权限、批量派发、任务确认 |
| Drawer | 需要参照列表或报表的编辑和详情。内容区滚动，主要表单操作放在底部 | 数据源参数、报表推送计划、焊接详情、运维记录 |
| 独立页面 | 有独立工作区或高信息密度的流程 | 报表设计器及其查询、定义和模板编辑区 |

## 破坏性操作

- 低风险且可恢复的操作可直接执行，例如移除草稿中的未提交字段。只有系统确实支持撤销时才提供撤销入口。
- 中风险且不影响其他业务的删除使用局部确认，按钮写明“删除监控”或“删除数据源”。表格行删除后，焦点移到仍可操作的控件。
- 涉及生产任务、权限、关联资源或大范围影响时使用集中确认。展示任务、账号、目标机床或关联范围，并保留原有校验。异步操作在请求处理期间禁止重入。

## 表单和草稿

- 业务组件跟踪修改状态和保存状态。关闭图标、Esc、取消和会覆盖输入的对象切换共用 `useUnsavedChanges` 返回的判断方法。含草稿的浮层关闭遮罩点击，确认框提供“继续编辑”和“放弃修改”。
- 未改动时直接关闭。放弃后再重置草稿。保存失败保留字段和表单错误，保存成功更新基准。避免在请求进行时覆盖或关闭正在提交的草稿。
- 路由离开由同一机制保护。仍会留在当前路由但会替换编辑对象的动作，需要调用判断方法。浏览器刷新和关闭由活跃页面的 `beforeunload` 保护。
- 尽量在同一个 Modal 内完成业务核对。独立的放弃确认使用 `useConfirm`，由 Naive UI 管理焦点、Esc 和浮层层级。

```ts
const canDiscard = useUnsavedChanges(dirty, '离开将丢弃尚未保存的连接参数。', saving)

async function closeEditor() {
  if (!await canDiscard('关闭将丢弃尚未保存的连接参数。')) return
  resetDraft()
  editorOpen.value = false
}
```

验收时用鼠标和键盘检查关闭和焦点返回，并覆盖窄屏、长文本、加载、失败、重复提交及放弃后重开。
