# 项目进度

> 更新日期：2026-09-15。

## 当前状态

系统已进入持续完善和内网联调阶段。标准报表、区间查询/导出、智能分析、工人确认、切割文件派发、告警报告和报表自动化均已有可运行实现。当前分支后端 433 项、前端 82 项测试通过，生产构建成功。

## 最近完成

- 兼容旧车间日报的工人撤销和管理员更正，并增加分类常用原因。
- 文件派发页支持从 PDM 直接单选或跨页多选，批量建任务后顺序下载、校验、上传和指派；推送成功后回收临时实体副本。
- 标准文件名自动识别材质和板厚；非标准名必须手工补全参数并明确确认。
- 统一页面与 HTML 报表的中文日期格式和期间排序。
- 全局表格采用内容驱动自适应列宽。
- 智能分析增加服务端数据版本、SQLite 版本缓存、前端 4 秒防抖和同版本并发合并。
- 车间报表翻页不再重置同一查询区间和数据版本的智能分析结果。
- 报表自动化页支持在线维护运行与 SMTP 参数，密码不回显，保存后重启生效。
- 文件派发在建任务时复核 PDM 版本和路径，历史物理记录不阻断重新派发。
- 修复缓存页面反复切换时隐藏查询、自动分析、图表、观察器和全局监听器继续运行的问题，并限制报表页面缓存数量。

## 当前问题

- 需在实际内网环境验证 SMTP 参数、定时生成、附件和失败重试全链路。
- 需在实际 PDM/FO/魔盒环境对批量推送、重复任务和推送后本地清理做验收。
- 前端生产构建存在单个图表相关 chunk 超过 500kB 的警告。
- 后端测试存在 Starlette `TestClient` 与 `httpx` 的一条弃用警告。

- 收集实际使用中的表格列宽、批量操作和分析触发反馈，只对有明确问题的页面微调。
- 单独评估图表依赖拆包与测试客户端依赖升级，不与无关功能修改混合。
