# 小组立焊接线接入

更新：2026-11-03。较早阶段验收记录保留当时结果；当前查询与快照规则以 AGENTS.md P09 和下述说明为准。

开发交付与现场验收分开进行：先部署本次代码，再由管理员在网页配置焊接连接。未配置真实数据库不阻止部署，焊接默认关闭；下文待现场验证的事项不作为继续编写代码的前置条件。

## 范围与入口

- 左栏按设备类型分组：切割下保留 Cutter01、Cutter02；焊接下为小组立焊接线。未来产线接入后复用类型分组，不显示未接入的占位产线。
- 已实现的小组立焊接线始终保留入口，目录返回 `enabled`；未启用页面引导数据库配置且不读取源库。设备和业务两栏共用主题父子菜单样式。
- 右栏按当前产线显示功能。焊接包含首页、生产统计、工件、作业、设备效能及适用设置；智能分析内嵌报表，不提供独立菜单。不显示告警、派发、工人任务或切割自动化。
- 所有管理员可访问焊接，工人不开放。原切割设备编号、目录接口、历史数据、默认选择及后台任务保持。
- `/admin/welding/home`、`/admin/welding/reports/{daily,parts,jobs,equipment}` 共用报表视图与现有主题组件，工件下钻为焊缝详情弹窗。旧 `/admin/welding/analysis` 保留日期查询参数并跳转生产统计报表，缓存标签不再展示独立分析页。
- 产线身份由焊接 API 前缀确定；切割 API 仍要求有效设备。网页请求附当前产线，后端拒绝焊接上下文调用切割专属操作。管理员仍可在切割上下文使用原有接口。

## 数据源与配置

管理员在数据库配置页填写焊接 MySQL 地址、实际端口、数据库、只读账号、密码、时区与启用开关，统一通过参数区底部“保存数据库配置”保存。焊接上下文只显示并独立保存焊接表单；切割上下文保存当前全部连接。测试统一放在下方“连接测试”区，可选择SQL Server或焊接MySQL，独立测试草稿不会自动保存或启用产线。业务数据源区同步显示焊接库状态，不泄露账号密码。

- 默认关闭 `WELD_ENABLED`，初始端口3306并不代表现场端口已验证。
- 保存至 `data/settings.env`，新请求生效。留空密码保留最近保存值，接口不回显密码；保存失败不发布新快照。
- 只改焊接配置时不重建切割服务；在途操作保留旧配置。原有全量保存兼容不含焊接字段的旧请求。
- 统一保存入口在切割参数未改变时按焊接独立保存处理；焊接配置文件只含焊接项时不校验未参与修改的SQL Server连接，避免本地切割库尚未配置导致焊接保存失败。修改切割、HR或文件连接时仍执行原完整性校验。
- 连接参数输入框的示例文字不代表已保存值；启用焊接时主机、库名、账号和首次密码必填。状态卡仅在配置完整时显示“已使用独立连接配置”。
- 连接测试仅执行只读事务中的 `SELECT 1`，不保存参数，也不代表业务表权限、字段或指标已验证。
- 使用 MySQL Connector/Python 内置连接池，延迟连接、默认4连接；实际 MySQL 操作按连接池配置采用至多4并发准入。
- 服务器对实际查询执行有界排队；前端不自动重放503。页面快照准备使用独立有界请求容量并按既有限次数轮询，离开页面或切换查询停止旧等待；导出、下钻和智能分析保留原请求语义。
- 默认连接超时5秒、每次SQL读写超时120秒，与切割生产库默认查询超时一致；同一只读快照内多条SQL不累计扣减。若调用方已有整体操作时限，则单次SQL以剩余时限为上限。SQL日志仅记录语句散列、耗时、行数、异常类型及数字错误码，不打印参数或驱动错误原文。
- 已有`.env`或`data/settings.env`显式设置`WELD_DB_QUERY_TIMEOUT_SECONDS=30`时会保留该覆盖值；现场统一120秒需将对应生效来源改为120并重建app/worker容器，不会静默覆盖现场设置。
- 超时、连接异常或回收失败后替换对应连接池；回滚失败仍尝试关闭连接，清理错误不覆盖原始查询/取消异常。不自动重放失败查询。
- 聚合先按查询范围筛选，再在不合并的派生表中预计算时间和流水号有效性，避免每个指标重复正则校验；关联质量按流水号预分组匹配，项目统计仅在工件报表执行。
- 不创建焊接告警或能耗，不写源库；统计预热和页面快照刷新复用 SQLite 队列与独立 Worker，详见 [多产线报表基础设施](multi-line-report-data.md)。Web/Worker 部署模式不变。

配置键见 `.env.example`：`WELD_ENABLED`、`WELD_DB_HOST/PORT/NAME/USER/PASSWORD/TIMEZONE`、`WELD_DB_POOL_SIZE`、`WELD_DB_CONNECT_TIMEOUT_SECONDS`、`WELD_DB_QUERY_TIMEOUT_SECONDS`。网页可编辑连接与时区，其余容量参数重启生效。

## 已确认统计口径

| 项目 | 规则 |
|---|---|
| 长度 | 三张明细表均按毫米读取，API、页面、导出统一米；SQL保留原始 `lenght` 拼写 |
| 日期 | 默认北京时间，零点划日；页面首尾日期均包含，查询转换为左闭右开；按作业结束时间归属 |
| 用时 | 使用源表 `used_time`，不以起止时间差替代；累计作业时间不代表设备开机时间 |
| 作业次数 | 按作业主键记录计数，要求结束时间可归属；包括所有源状态，不能解读为完成次数 |
| 涉及工件 | 按区间有效作业中的有效完整流水号去重；不补项目前缀或模糊合并 |
| 长度与用时有效性 | 分别排除非正长度、非正用时；某字段无效不抹去其他指标 |
| 单位用时产出 | 同一批正长度、正用时且结束时间有效的作业，米数除以累计小时数 |
| 工艺 | 支持0平焊包角、1平焊、2立焊包角、3立焊及未知代码；包角类型单列，附加长度不再次累计 |
| 机器人 | 按作业表的设备与机器人组合统计工位；不推断物理机器人数量 |
| 工件报表 | 区间参与过焊接的工件；工件自身长度明确标为累计值；多条流水号归属使累计总量待核实 |
| 焊缝关联 | 完整流水号精确匹配，先检查工件归属唯一；歧义不展示猜测结果，不要求未确认的机器人映射一致 |
| 项目图 | 仅统计流水号归属唯一且参与有效区间作业的工件，最多展示前100个项目并提示范围 |
| 未知值 | 返回null并显示待核实；真实无记录可返回0，源库故障不能转为0 |

各表 `state` 没有套用统一字典。完成工件数、完成趋势、综合燃弧率和整体焊接率暂不启用；明细中的源表比例注明待核实。负长度、异常比率、耗时关系、无效时间和流水号保留追溯提示，不清洗源库。

源表更新时间与计算时间分别展示。排除原因可重叠；完全无法归入区间的时间异常由独立核验统计，不强行分配生产日。

## API

沿用 `success/data/request_id` 包装与管理员认证。

| 路径（前缀 `/api/v1`） | 用途 |
|---|---|
| `GET /production-lines` | 按类型提供可用产线/设备及能力，不触发源库连接 |
| `GET /welding/health` | 源库状态、设备目录及三表最新更新时间 |
| `GET /welding/dashboard` | 今日KPI、指定区间趋势、最新10条作业，共用读取快照 |
| `GET /welding/statistics/daily` | 日汇总 |
| `GET /welding/parts`、`/jobs`、`/equipment/summary` | 工件、作业、设备机器人工位报表 |
| `GET /welding/parts/{id}`、`/{id}/seams` | 工件及分页焊缝 |
| `GET /welding/parts/{id}/seams/export` | 当前工件全部焊缝CSV |
| `GET /welding/export` | 四类报表CSV、HTML或PDF |
| `POST /welding/analysis` | 当前查询汇总的AI分析 |
| `PUT /database/welding/configuration` | 单独保存焊接连接并热加载 |
| `POST /database/welding/test-connection` | 不保存的只读连接测试 |

报表参数：`start/end`、`device_no/robot_no/weld_type/state`、`serial_number/project_no/section_no/part_no`、`anomalies_only`、`page/page_size`、`sort_by/descending`。工件状态内部规范化为 `part_state`，不会误用于作业状态。文本精确匹配，值参数绑定；重复或未知参数拒绝。最长366天，每页默认20、最大100；排序仅允许time、length、id。

导出另含 `report_type=daily|parts|jobs|equipment` 和 `format=csv|html|pdf`。导出全部筛选结果：CSV最多100,000行，HTML/PDF最多5,000行；超限拒绝，不截断。同一读取快照取得统计和明细，包含筛选、来源、单位、时间。CSV防公式注入；HTML自动转义并内嵌图表；PDF复用Chromium渲染及容量限制。文件仅用于本次下载，不增加焊接历史中心或自动发送。

分析体为 `{report_type, query, data_version}`。仅发送汇总、日趋势、设备工位和数据质量，使用焊接专属提示词，复用模型限流、超时、输出验证和用量记录。版本包含筛选、汇总、源更新和关联质量，不符时返回409。进程内缓存最多16个版本、5分钟，不跨源配置共享。模型失败不影响报表和导出。

## 核验与部署

1. 按原Docker/Linux流程重建镜像，`backend/requirements.txt` 已包含MySQL驱动；原打包脚本包含新增后端、前端源码。

3. 在实际部署后端执行：

   ```bash
   docker compose exec app python scripts/check_welding.py --end 2026-10-23 --runs 3
   ```

   本地开发可执行 `./.venv/bin/python scripts/check_welding.py` 并传相同参数。日期换为现场典型生产日。脚本检查授权类型、字段、索引、状态、重复流水号、不可归属时间，记录日/周/月四类报表服务耗时。授权原文、凭据不输出；没有权限的两张可选表单独标记，不影响核心三表核验。服务耗时不是HTTP端到端延迟，低样本P95只作初查；现场还应记录页面、导出、连接占用和慢查询。索引变更交DBA，不在脚本中执行。
4. 部署并保存连接后，核对同条件源记录、页面和导出，测试焊接断连与切割原功能。现场验收通过才视为真实接入完成；这一现场阶段在代码开发交付之后进行。
5. 回滚先关闭焊接开关。无源库或SQLite数据迁移，不恢复或覆盖历史数据库；保留旧镜像可回退应用。

## 查询可靠性修复

焊接HTTP执行容量由 `min(4, WELD_DB_POOL_SIZE)` 决定，连接池默认4；显式较小连接池不被覆盖。执行位满后最多12个请求按FIFO异步等待5秒，排队不占执行线程或数据库连接；队满与排队超时返回503及 `X-Workload-Error`。取消等待不会迟到执行，运行中的同步工作结束后才释放容量。其他业务池保留原有立即拒绝策略。

PDF分为数据/HTML准备与渲染两阶段；前者占焊接查询位，结束后再进入既有PDF请求池与跨进程单渲染限制。AI重读数据也走焊接查询池，模型阶段仍走原分析容量及全局模型限制。CSV/HTML保持全部筛选结果及既有限额。作业列表复用同一一致性事务汇总的 `source_rows`，省去一次重复COUNT；无效时间候选仍计入列表总数。分页统计复用规则见下节；导出仍在当前快照重算全部必要指标。

前端相同条件的在途查询复用，改条件取消旧请求，过期结果不能覆盖；主动刷新在上次完成后仍会重新查询。服务器负责有界等待，前端不再按503循环重试。错误日志仅记录请求/执行ID、操作名、等待/执行耗时、SQL哈希、行数、错误类型与错误码；`X-Welding-Error` 区分连接池耗尽、查询超时、认证/授权、表结构、SQL及连接故障，不输出凭据或SQL参数。

部署时同步 `WELD_DB_POOL_SIZE=4`、`WELD_DB_QUERY_TIMEOUT_SECONDS=120` 并重建容器；若 `data/settings.env` 有同名值，以该文件为准。没有修改生产库、索引或SQLite结构。真实慢查询、连接中断和现场多用户表现仍须通过只读日志及抽样验证。

报表读取分为公共统计（汇总、趋势、设备分布、关联质量）、报表专属统计（项目、速度分布、工件累计及数量）和当页明细。缓存键包含规范化筛选、源表更新时间和设备目录，排除页码、页大小及排序；公共统计可跨报表类型复用，专属统计按类型隔离。每次请求仍在当前只读事务核对源信息；命中后作业/工件只查询当页明细，工件不再重复 COUNT。报表字段、单位、过滤和分析版本算法保持。

每个服务实例最多保留32份统计，有效期30秒；返回副本避免报表专属字段污染公共缓存，失败不缓存。源表更新时间全部缺失时不缓存；连接/时区热配置重建焊接服务后缓存自然隔离，旧请求继续使用原服务。导出绕过统计缓存，仍在一个一致性快照计算全部内容并应用原行数限制。

源库 `MAX(update_date)` 是更新时间水位，不是严格变更版本。没有推进最大更新时间的修改或删除，页面统计可能在30秒内短暂落后于明细；若现场要求严格实时一致，应先提供可靠变更版本或禁用跨请求复用。当前仍需读取源信息，未承诺分页只发一条 SQL，也没有生产性能提升百分比；现场须补充慢查询与执行计划证据。
