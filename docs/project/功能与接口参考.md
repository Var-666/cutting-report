## 报表与查询口径

切割领导、车间、设备报表的任务统计口径：仅统计 `STATUS = 2` 且 `WORK_TIME >= 0` 的任务，负工时异常任务整条剔除；统一按实际 `END_TIME` 的日期归属任务，跨日/跨月任务完整计入结束当天/当月；结束时间缺失或无效的任务不计入，不回退 `OP_DATE` 或 `START_TIME`；切割和坡口长度由毫米换算为米；`WORK_TIME` 按秒汇总；历史对比覆盖所选月份及其前十一个月；图表时间轴从左到右递增；不按 `PORTION_ID` 去重。生产日期用于筛选及归组，表内开始时间和实际能耗时间窗口保持原值。历史车间日报按[部署校正步骤](../deployment/OFFLINE_DOCKER部署说明.md#切割任务改按结束日期统计)迁移并保留确认，已归档HTML/PDF及已发送邮件不追溯改写，需重新生成。

领导报表使用“内存缓存 + 应用 SQLite 月快照”，页面优先显示最近一次成功快照，过期数据由独立 Worker 更新；当前月默认每 300 秒刷新，最近三个月每天校准，其他历史月在被查询且过期时刷新，首次启动会预热最近十三个月。普通月份查询不会绕过缓存，“刷新最新数据”会提交后台刷新且不阻塞页面。SQL Server 查询在一个连接内使用会话临时表完成每日和工程聚合，不修改生产数据库表。当前周期三类标准报表在 SQL Server 模式下每 300 秒后台刷新；已启用大模型时，每轮强制重新调用对应模型，即使数据未变；上一轮正在执行时新一轮仍独立并行，普通页面查询继续读取缓存；积压合并、有界重试与过期处理见[后台队列策略](architecture.md#后台角色队列与恢复)。间隔由 `REPORT_BACKGROUND_REFRESH_SECONDS` 控制；页面查询缓存仍由 `LEADERSHIP_REPORT_CACHE_SECONDS`、`REPORT_DATA_CACHE_SECONDS` 控制。

管理员登录后进入跨产线生产总览，各自产线概览和公共设置的入口归属见[公共导航与产线范围](architecture.md#公共导航与产线范围)；“生成与历史”继续作为切割报表栏目下的功能页保留。

登录成功或恢复会话后，前端只预加载当前路由所需报表，按任务串行执行；设备页内部可并行读取任务与日能耗。请求与短期结果保存在会话内存，退出或切换账号清空；手动刷新绕过缓存。预加载不执行文件派发、HTML生成或大模型分析。工人确认状态按既有轮询更新。

同一浏览器会话中，已打开的领导、车间和设备报表在离开到首页等模块后仍保留页面数据；返回相同日期时立即展示已有内容，并按已提交的条件在后台读取最新数据，更新期间标明当前显示上次加载的数据，失败保留同一日期的数据并提示错误。管理员车间及设备报表默认查询当天（Asia/Shanghai），跨日返回时清除旧日期的任务数据；当天或所选区间无任务直接显示空状态，不自动回退到历史有数据的日期，预加载遵循同一规则。手动查询、导出、智能分析、取消及能耗补数轮询沿用原校验。缓存仅保留当前设备的一组、最多三个报表页，切换设备或退出会话时销毁；未访问过的页面、整页刷新及新会话仍需首次加载，不将生产数据写入浏览器持久化存储。

- 领导报表支持自定义起止日期，包含区间汇总、每日长度/工时趋势和按月汇总；
- 车间报表支持自定义起止日期，包含生产指标、任务切割长度/坡口长度/工时组合图、任务明细和工人确认统计；管理员区间查询不会为各日额外创建车间快照；
- 设备报表支持自定义起止日期，同页展示区间任务能耗和按日汇总；SQL Server 模式通过能管接口按任务实际起止时间计算气耗、电耗。未配置、未绑定、缺数或接口失败时显示 `--`，不回退到模拟值。只有显式 `demo` 模式生成标注清楚的演示能耗，不能用于结算或考核。

三类内置报表的自定义区间均为闭区间（包含开始日和结束日）。领导和车间报表最长 366 天；设备任务能耗涉及能管平台实时采集值，自定义区间最长 31 天，近 12 个月趋势使用默认月度汇总接口。页面查询和 HTML/PDF 导出使用同一区间，导出文件名及“生成与历史”会保留完整起止日期。区间智能分析使用紧邻的前一个等长区间作为对比。
领导报表生成请求仅传 `report_date` 时仍按所属自然月统计；只有显式传入非空起止日期字段才按自定义区间处理，`null` 与未提供一致，日期校验补齐的值不能将月报误判为单日报表。已生成的错误区间报告需重新生成，不追溯改写。
统计区间在三张报表中复用同一弹出式选择器，提供单日、最近 7 天、跨月近 30 天、本月、上月、本季度和上季度快捷项；点击“应用”只更新条件，仍需点击“查询报表”才读取数据。

三类报表均包含报表专用智能分析；未配置模型且没有成功缓存时等待模型恢复，不发布缺少分析的新报告，不用规则结果代替。当前周期由后台每轮强制重析；自定义区间仍按需查询与分析。

设备报表拥有独立展示页，进入后默认查询当天，当天无任务显示“所选区间暂无任务”；手动选择历史区间时仍可查询该区间。任务明细按“序号、工程号、船号、分段名、开始时间、切割时长、电耗、气耗”展示；近12个月月度汇总继续按其明确展示的月份范围统计。

切割任务未返回工程号、船名或分段名时（包括null、空字符串及空白），车间、设备和工人确认相关展示统一使用 `--` 占位；原始字段和已有有效内容保持不变。

设备页面和导出文件的图表只使用上述明细表可见字段：以开始时间为横轴，展示切割时长、气耗和电耗；不使用隐藏的设备编号、切割长度或任务数生成额外图表。

## 数据库端口监控

管理员在“系统设置 → 数据库监控”中添加名称、单个IPv4/IPv6地址和实际端口，支持编辑、暂停/启用和删除；同一IP/端口不能重复登记，不需要数据库账号密码。目标独立于产线和业务数据源，关闭浏览器后仍由后台检测。

每60秒一轮，每次TCP连接最长5秒。首次失败显示“异常待确认”，连续3次失败形成一条故障事件，连续2次成功记录“已恢复”；同一次故障不重复建事件。超过180秒未获得检测结果显示“状态未知”，检测中断后重新累计连续次数。多个慢目标或后台排队可能延迟轮次，过期任务不集中补探测，不把旧结果标为正常。端口可达仅证明网络端口接受连接，无法据此证明数据库查询正常或确定故障一定来自关机。

修改地址、暂停或删除会终止当前事件，并分别标注“目标已变更／已暂停监控／已删除监控”，不能记作数据库恢复；重新启用或换地址后从“状态未知”重新检测。删除目标保留故障历史。页面每15秒读取后台结果，显示名称、IP、端口、状态、检测时间、故障开始、持续时长及失败原因；故障记录按页查看，时间使用应用时区。接口 `/api/v1/database-monitors` 仅管理员访问，新增/修改使用POST/PUT，移除使用DELETE，历史通过 `/incidents/page` 读取。

008迁移通过既有[PostgreSQL普通更新流程](../deployment/OFFLINE_DOCKER部署说明.md#已有postgresql更新)执行，不在应用启动时建表。系统自身PostgreSQL不可用时站内记录与读取也会受影响；本功能不提供独立外部探针或通知通道。

## 智能分析依据

切割领导、车间、设备分析使用动态生产简报，页面原有KPI、图表和表格保留。默认周期分别为完整自然月、当天、当天；自定义区间使用实际闭区间。自然月仅与明确的上一自然月比较，自定义区间仅使用紧邻等长周期，不能把历史趋势中的任意一项当作可比数据。

- 模型输入：`scope`（产线、类型、实际起止日期、模式、明确比较日期）、`facts`（后端权威事实）、`candidates`（稳定候选ID、类别、事实引用、对象预览及解释边界）、`tables`、`data_quality`、已有分布汇总及 `output_schema`（来自现有Pydantic输入模型，候选与指标编号限定为本次允许值）。使用原JSON模式并提供结构示例，不依赖供应商专属结构化接口。任务表只发支持候选的必要样本，汇总表最多40行，工程/设备分布最多10组；每项保留完整总量和覆盖说明。输入仍受原配置容量限制，超限明确报错，不分批调用模型。
- 模型输出：`headline`、`summary`、`key_metric_ids`（0～3项）、`findings[{candidate_id,title,detail}]`、`actions[{candidate_id,title,detail}]`。业务数量、单位、百分比和时长优先写为 `{{F001}}` 形式的事实占位符，由后端填入对应事实的原值；未知或格式错误的占位符拒绝。省略的 `evidence_ids` 由后端按有效候选绑定，旧模型若显式提交仍按原规则严格检查；公开结果中该字段继续必填，HTTP响应契约不变。发现和建议可为空；模型不能提交业务主键。后端核验结构、候选/事实存在性、建议归属及数量、日期、百分比方向，再补 `scope/data_quality/references/reference_count`。兼容旧模型直接写出的数值：中文时长按末位单位精度取整且相对误差不超过2%，`HH:MM:SS`按秒准确核对；长度、能耗和百分比允许同单位四舍五入。任务数、日期和引用保持准确。待确认占比由后端按全部任务计算后提供，空任务不生成占比，不使用样本计算比例；少量行文序号不作为业务数量，内部编号不参与数字授权。
- 百分比校验同时识别中文事实中的涨跌值和 `comparisons` 内由后端计算的 `*_percent` 字段，按正负核对方向并允许展示精度取整；不把空比较值或无关输入数字当作变化率依据。包含业务时区当天的统计区间在 `data_quality` 标注“周期尚未结束”，对上一完整周期的任务量变化仅作进度参考；历史及纯未来区间不加此提示。该说明参与分析缓存指纹，同一天不因时钟推进重复调用模型，周期结束后移除提示并重新生成。待确认数量与任务总数变化分别表述。
- 最终结果新增可选 `brief`；原四个字段通过确定性适配保留，模型不再生成四段切割分析。历史分析JSON无需重写；新提示词版本隔离正常生成缓存；可用性回退沿用同范围的历史成功模型分析及原生成时间，网页、HTML/PDF和邮件不显示历史缓存说明横幅，内部 `cache_note` 继续隔离新旧数据。焊接仍用原四字段，告警不受影响。默认页最新结果轮询、版本校验、取消、单飞及失败保留仍沿用原流程。
- 百分比的“约／大约”、空格、全角百分号统一参与方向核验；长度校验同时读取实际发送给模型的明细和分布中的切割/坡口长度字段，不把任务数或其他单位的数值作为米数。设备生产概况允许引用已提供的任务变化、切割时长和工程分布，领导周期对比允许引用已提供的同期事实；未知或无关引用继续拒绝。日志按设备、报表类型、周期及 `analysis_id` 定位，拒绝引用时记录候选和有界的允许/返回编号，数量、单位、时长及百分比错误记录有界的被拒绝表达。结构错误只记录有界字段路径和错误类型，不记录模型原文；报告等待分析的日志直接包含 `report_id`、类型和原因。v29校验版本隔离正常生成缓存。
- 完整关联集合保存在原 PostgreSQL 分析JSON中，并随结果返回；页面只预览前3项，任务优先显示程序、工程及分段等业务信息；旧缓存按已有程序/工程字段转换显示，缺失时明确提示业务信息未填写，不用裸任务ID充当名称。弹窗按10项分页查看全部，原ID在“记录编号”列保留，明确展示分析时记录及生成时间。任务点击后前往车间报表，携带原起止日期、`task` 和 `task_line`；`/api/v1/workshop/range?task_id=...` 在原产线及日期查询结果中精确筛选真实任务ID，不存在则返回空。产线不匹配时禁用跳转，后台仍通过原管理员/设备权限边界。未新建任务管理系统或独立关联存储。
- 前端按结论、按需指标、动态发现、按需跟进、折叠依据阅读；新简报不重复固定六指标或四卡片。HTML/PDF 使用同一 `brief`，导出中展开依据以供打印；旧结构仍兼容。

新报告分析先校验本次数据，匹配版本可复用，数据变化先重析，失败才沿用同范围历史成功结果：

- 页面更新失败保留同范围成功内容；默认页首次没有结果时显式发起分析，失败后遵守 `Retry-After: 60` 再尝试，失活或隐藏时不轮询。新HTML/PDF与邮件报告先按本次数据构建分析输入，仅复用当前数据版本、输入、模型及提示词匹配的成功结果；数据或输入变化则重新分析，分析准备或模型执行失败后才回退同范围历史成功结果，保留原时间、版本及事实。取消与版本冲突不回退。既无本次成功结果也无历史成功缓存时，切割报告任务保持 `pending/ai_status=waiting`，不发布文件或创建发送任务；Consumer按1、2、4、8、16、32分钟退避，之后最多每小时重试，重启后仍由原队列继续。焊接HTML/PDF同步返回503及 `Retry-After: 60`，CSV只导出生产数据，不触发分析。
- 页面失败提示保留超时、限流、认证、连接及输出校验等具体类别，不统一改写为“等待成功”；后端日志保留校验原因供排查，响应不暴露模型原文、凭据或内部引用编号。HTTP 200 的模型用量记录只表示已收到接口响应，不表示分析已通过后续业务校验。
- 切割和焊接的有效接口响应若未通过输出校验，在同次操作中最多反馈一次具体校验原因，要求模型返回完整修正版；修正版仍须通过全部校验，持续失败保留原错误/历史成功回退。两次调用共用原排队与总执行时限，纠错内容计入输入容量，每次HTTP请求分别统计真实用量。连接、认证、超时和损坏的接口响应不因输出纠错额外调用；原429退避保持。参考 [DeepSeek JSON输出](https://api-docs.deepseek.com/guides/json_mode/) 和 [Pydantic 输出校验反馈](https://pydantic.dev/docs/ai/core-concepts/output/)，不新增SDK依赖。
- 可复用范围包含设备、数据源、报表类型、实际日期/区间、筛选、汇总窗口及设备能耗单位，不跨范围借用。允许沿用换模型或提示词之前的成功结果；原 `generated_at/data_version/facts` 保持不变，新增 `cache_note` 提醒分析依据为旧数据。旧分析区域不混入本次数据的新趋势、日均值或工程汇总。导出仍需完成当前生产数据校验。
- 009迁移为成功缓存增加范围索引，为报表任务保存重试次数及下次时间。旧默认周期的已发布成功分析可按已有来源与日期复用；无法确认筛选来源的旧自定义分析不推测归属。已归档报告和已发送邮件不追溯改写；持续无成功模型且无缓存时，任务会继续等待。

判断边界：数字、日期和引用校验不能替代完整语义审核，不保证模型自由叙述的因果解释正确。领导聚合报表只能绑定已有工程或日期，不能从汇总虚构任务。关联弹窗是分析时快照，当前确认状态以点击后重新查询为准；完整关联随分析JSON传输，极大任务集合会增加响应体大小，模型输入容量仍单独受限。缺少计划、订单、开机时长或一致能耗覆盖时，不输出对应完成率、停机率、利用率或能源效率结论。

## 能耗统计与接口

### 设备任务与日/月汇总

设备报表在同一页面显示任务能耗和日/月汇总。任务来自生产 SQL Server，按 `devices.json` 中当前设备的机号、历史别名和仪表组计算。Cutter01 使用已确认的气表及 DH01/DH02/DH03 电表；Cutter02 暂未绑定仪表，不汇入 Cutter01。

- 当日任务表每个任务一行，末行为当日任务汇总，左侧显示任务电耗/气耗双轴图。
- 月度表包含所选自然月的全部日期（支持闰年），每个日期一行，末行为当月汇总，
  左侧显示逐日双轴图。
- 任务能耗严格使用每项任务的实际 `START_TIME` / `END_TIME`；任务时间重叠时不重复
  分配同一仪表耗量，相关行保留缺失及原因。
- 查询单日后，将小时明细、读数边界依据和日合计保存到 PostgreSQL
  `energy_daily_snapshots`。不保存能管密码或授权码，也不修改能管平台数据。
- “查看月份”读取已保存记录；“同步本月”依次查询未保存日期及今日；
  “重新查询本月”重新查询全部已到日期。同步有进度、可以停止；已完成日期不会丢失。
  当前最新生产日还会由后台定时更新；历史日期仍按需查询与保存，历史记录不会在月底自动删除。
- 小时区间严格使用整点至下一整点；全天为本地时区 00:00 至次日 00:00。
  不能将当天第一条、最后一条读数直接当作日界。今日只统计已结束小时，未结束小时和未来日期不填零。
- 合计只加有效小时/日期；缺失保持 `--`，页面展示实际有数据的小时数和日期数。
  所选电表任意一块缺数时，该小时电耗整体缺失；非精确边界按配置规则进行插值估算，不在数值前添加符号。
- 日/月报的历史阈值为 `ENERGY_REPORT_MAX_GAP_SECONDS=1800`，
  旧设备任务接口的历史阈值为 `ENERGY_MAX_GAP_SECONDS=300`。
  按已确认日期，默认从 `ENERGY_SAMPLING_CHANGE_AT=2026-09-04T00:00:00+08:00`
  起，使用 `ENERGY_NEW_MAX_GAP_SECONDS=180`：日/月汇总中连续超过3分钟无读数的
  区间不计入有效耗量，保留缺口原因，不填零。任务明细允许累计读数估算，规则见下文。允许正常一分钟采样的轻微抖动。
  跨切换点的相邻采样分别校验切换前后的间隔；插值规则、单位换算和60秒接口缓存不变。
  切换时间可配置，无时区时按 `APP_TIMEZONE` 解释，显式留空关闭新规则。
- 切换前的完整日期直接沿用原快照；受新规则影响的日期使用独立快照，旧记录不删除。
  旧结果未重新校验前不计入新规则的月合计，页面提示待重新同步的天数。
  点击“同步本月”可补齐；新查询不会因新规则认定缺数而退回旧规则的有效数值。
- 电耗单位统一使用 `kWh`（1 kWh = 1 度电），气量单位使用 `Nm³`。
- 保存记录按接口地址、账号标识、参数组、单位、换算因子、时区和计算规则隔离。
  修改这些配置后不会混用旧口径记录。网络/认证失败，或有效时段减少时，不覆盖此前已保存的较完整记录，并提示保留原因。

接口：管理员会话下 `GET /api/v1/energy-report/tasks?device_id=Cutter01&report_date=YYYY-MM-DD&refresh=true`
查询任务能耗；`GET /api/v1/energy-report/day?device_id=Cutter01&report_date=YYYY-MM-DD&refresh=true` 查询并保存
全天内部统计；`GET /api/v1/energy-report/month?device_id=Cutter01&report_month=YYYY-MM` 读取整月记录。设备页面的近 12 个月汇总优先返回已保存快照，缺失历史月由后台线程按周分片从能管平台补齐，页面自动更新，不阻塞登录和首屏。

### 任务能耗质量规则

网页、HTML 导出和智能分析统一使用 `EquipmentEnergyService`。气量单位已确认为 **Nm³**。
密码、CompanyId、AuthId 不进入前端、日志或导出文件；接口只使用登录和采集值查询，不调用 `SaveCollectValue`。

能管账号、参数及联调命令见 [配置参考](../deployment/配置参考.md)。仪表编号以设备目录为准，不在多份文档重复维护。

采集接口返回 `MfId / Mt / Mv`。客户端兼容数组、JSON 字符串和 `Content` 包装，登录自动获取 CompanyId/AuthId，鉴权过期最多重登一次；网络失败短暂退避，页面、导出与分析共享短期读数缓存。查询按最多 24 小时拆分，不同时间片只在各自的锁内合并重复请求，不会用一次长区间查询阻塞所有能耗请求；系统不长期保存原始采集数据。

计算及质量口径：

- 必须精确匹配 `MACHINE_NO`；可配置同一设备的历史别名，但不能关联多台不同设备。
- 气耗 = 累计气量结束读数 − 开始读数；电耗 = 已确认的电表各自正向有功电能差值之和。任一所选电表缺数时，该任务电耗整体缺失，不伪造少表的合计值。
- 使用任务 `START_TIME` 和 **实际 `END_TIME`**，支持跨午夜；不以 `START_TIME + WORK_TIME` 冒充结束时刻。无效时间或同一计量设备在查询任务集中存在重叠时，不分摊、不重复计量。跨报表日的重叠任务仍需现场核对。
- 非采样时刻的起止边界优先用相邻读数线性插值。任务区间内部采样稀疏时，仍使用有效累计读数差，标记 `estimated`；首尾未完整覆盖时，按“已覆盖耗量 ÷ 已覆盖秒数 × 任务总秒数”估算，保留有效覆盖时段、原始耗量和计算方式。需至少两条不同时间的有效读数且覆盖任务的部分时段；没有读数、只有一个采样点、回零/倒退、负值、非有限数、同刻冲突及任务重叠仍保留缺失，不填零。
- `ENERGY_ALLOW_INTERPOLATION=false` 时保留严格模式，不启用稀疏采样或首尾补估。页面与HTML导出只显示数值，悬停查看估算依据；汇总及智能分析计入估算结果并保留估算数量。平均速率补估假设未覆盖时段耗用均匀，日/月小时快照仍采用原来的完整边界和采样间隔规则。
- 文档注明上传的 `Mv` 已乘读数因子，默认转换因子为 1，不重复乘 CT/PT。若实际返回单位不是目标单位，必须经确认后设置转换因子；不从“2万瓦”额定功率反推用电量。
- KPI 是**已匹配任务时间区间耗量**（含该区间内待机），不是全天总用量或纯切割净耗；分别展示气、电有效记录覆盖数。空值不作为零，真实零耗量可正常显示。插值值和缺失不可用于结算或直接判定能耗异常。

三类内置报表均可在生成前选择柱线组合、柱状图、折线图或面积图。领导报表的页面图表会立即切换，所选类型同时写入导出的 HTML；车间和设备报表在导出时应用所选类型。自定义报表定义也支持这四种图形。

领导、车间、设备、自定义、焊接各类及告警报表的 HTML、PDF、邮件共用工业风视觉：`industrial_chrome.html.j2`、`industrial_report.css.j2`、`industrial_report.js.j2` 维护品牌栏、深蓝青色、指标、表格和分析样式；领导报表继续使用专属内容模板。HTML 连续展示，窄屏表格内部滚动；PDF 按内容实际宽高生成单张连续长页，宽表保留完整列，不固定 A4、不强制章节换页、不重复页眉页脚、不显示页码。长表和长分析完整保留；摘要与证据使用真实报表/分析内容，历史分析保留原日期与事实。切割报表不展示独立备注列，源数据仍保留。历史 HTML 及已缓存 PDF 不会自动套用新模板，需要重新生成报告。

网页及导出日期的月、日统一补足两位：中文显示为 `2026年09月01日`、月份为 `2026年09月`，已有 ISO 日期保留 `2026-09-01`；时间保持两位时、分、秒。前端复用 `utils/dateDisplay.ts`，Jinja 报表复用 `ReportService` 的日期过滤器，查询参数与日期归属不变。

切割任务的工程号优先取去除首尾空格后非空的 `PROJECT_NAME`，为空时回退到 `PROJECT_CODE`；两个源字段都为空时保持缺失，不根据文件名推测。船名沿用BM精确映射，工程统计仍使用完整工程编号。每台设备每个生产日期只有一份车间日报：同步时按设备及任务ID更新已有任务的工程号、分段、程序号、长度、工时、开始时间、备注及生产日期，并追加新任务；生产字段后补或修正不会阻断整份日报显示，不删除本次查询未返回的既有记录。任务、日报身份及已有确认人、确认时间、确认审计记录保持不变。任务内容更新时递增该任务的快照修订号，旧页面提交确认须刷新后使用新版本；仅补缺失工程编号或船名继续保留原修订号。同步无内容变化不重复更新。分页和筛选只影响展示，所有工人均可查看整份报表；导出及工人工时汇总读取更新后的日报数据。

人工确认以 `(scope_machine_no, TASK_ID)` 为任务键，表示“这个任务是我完成的”，一个任务只能由一个登录账号确认。当前确认保存在 `workshop_confirmations`，确认、工人撤销、管理员撤销和改派写入 `workshop_confirmation_audits`，均只修改系统 SQLite，不修改生产库 `dbo.task`。车间 HTML/PDF 导出使用同一份日报快照，生成时会固化当时的确认人；之后变更确认需重新执行导出。

## 账号与车间确认

支持可选 OIDC 统一认证：`GET /api/v1/auth/sso/login?return_to=站内路径` 发起登录，`GET /api/v1/auth/sso/callback` 验证并消费一次性回调，`GET /api/v1/auth/status` 返回 `sso_enabled`。统一认证从认证中心门户的本站入口发起，本站登录页保留账号密码表单，不显示统一认证按钮或自动跳转。按现场确认的 `sub=HR._Identify` 精确对应本站已有HR账号，包括已授权管理员；本地/特殊账号保留显式绑定并优先处理。保留原账号ID、角色、确认历史及本站会话，不创建或启用账号、不授予角色。无对应账号、停用或身份验证失败时拒绝登录；保留账号密码回退和本站退出，不提供全局退出。配置、迁移与验收统一见[配置参考](../deployment/配置参考.md#oidc-统一认证)。

系统首次启动且管理员账号表为空时，登录页会要求创建首个本地管理员账号。启用工人数据库认证后，工人使用集团工号和 HR 数据库中的密码登录，本地应急管理员继续使用本系统账号，已授权的 HR 管理员使用集团工号登录。任意已登录员工首次进入当日页面时，系统会幂等地生成或读取当前设备当日唯一报表；页面每 5 秒静默同步一次其他员工的确认结果。点击“确认是我完成”后，系统立即记录当前账号姓名和确认时间，不允许第二个人覆盖。工人可在“撤销我的确认”中填写原因后撤销本人记录；管理员可将已确认任务恢复为待确认，或改派给已在系统登录过的可用工人。撤销和改派原因均为必填项。

工人认证读取 SQL Server 的 `dbo.HRbase_userInfo`，字段映射为：`集团工号`是登录账号、`密码`在 SQL Server 内直接比较、`_Identify`是稳定人员标识、`姓名`是显示姓名，同时读取`公司工号`和`可用`。不读取或校验 `_Locked`，无论它是 NULL、0 还是 1，都不影响本系统登录；集团工号唯一性、密码、可用状态和人员信息完整性校验仍保留。明文密码不会被查询返回、写入本地 PostgreSQL、Session 或普通日志。工人首次登录成功时，系统只在 PostgreSQL 创建一条不含密码的影子身份，用于会话和任务确认外键。

统一登录接口 `/api/v1/auth/login` 仍使用 `username/password`，其中 HR 账号的 `username` 为集团工号。HR 专用接口 `/api/v1/auth/hr-login` 及旧路径 `/api/v1/auth/worker-login` 使用 `group_no/password`，不再接受 `company_no` 作为登录字段。管理员密码复核同样按集团工号查询；人员搜索支持姓名、集团工号和公司工号。身份仍以 `_Identify` 绑定既有用户，集团工号变更不新建账号，不改变已有权限和任务确认记录。

HR、PDM、文件服务及 Cookie 的连接与启用参数见 [配置参考](../deployment/配置参考.md)。

## 文件派发与 PDM 接口

管理员从 `/admin/cutting-dispatch` 按项目和目录选择文件、填写参数并确认派发。同一页面整合文件选择与执行；旧 `/downloads`、`/push` 地址重定向到该页面。

- 原派发记录上方默认展示最近7天（含当天，Asia/Shanghai）的每日派发与完成趋势，支持最长366天日期区间和机床筛选；点击柱子或在“查看某日明细”选择派发/完成后，原分页表展示对应文件。点击日期或图表内该日期列的空白区域时，只有完成记录的日期自动展示完成明细，其他日期默认展示派发明细；直接点击不同柱子仍分别展示对应类型。清除筛选将趋势恢复最近7天、明细恢复全部记录，待处理/失败记录仍可查；派发完成后刷新趋势与明细，离页取消请求并释放图表。趋势失败不阻断原记录查询。
- 成功量按真实任务首次 `sent_at` 及应用时区归日，同一派发任务重试不累加，数量参数不作为文件次数；同一文件向不同机床的独立派发分别计数。模拟、仅下载、上传成功但未确认指派，以及从未确认成功的结果未知记录不计入；成功后撤销仍保留原成功量。新增表列“成功派发时间”按同一时区显示。统计只查本地SQLite已保留记录，不访问PDM/魔盒；清理前已删除的历史不能补回，旧版曾被覆盖的成功时间也不能追溯还原。
- `GET /api/v1/cutting/dispatches/trend?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&machine_ip=可选` 返回每日零值补齐序列和历史机床选项。原 `GET /dispatches` 增加同名筛选，传日期时按真实成功时间过滤、排序，必须同时提供起止日期；不传日期保留原全状态记录与创建时间排序。两接口均保持管理员权限；分页总数与明细使用同一谓词及只读快照。首次成功时间在原状态迁移事务内固定，无新增数据库表或后台任务。

- 项目搜索与选择共用下拉框，确认项目后读取目录，再按目录分页查询文件。
- 推送绑定文档、版本及路径，复核大小和 SHA-256；需要时先从 FO 下载，再上传魔盒和指派机床。
- 派发记录保存船号 `ship_no`、分段号 `segment_name`；标准分段由现有文件名规则提取，非标准分段在人工复核后随实际上传参数保存。SQLite增量添加可空字段，既有记录不猜填船号；列表读取仍只查本地库。
- `taskName` 按 `船号_分段名_实际上传文件名（含扩展名）` 拼接，例如 `CMIP-F262004_806C_Z806C080A001.gen`；船号取 PDM `ShipNo`（项目下拉中间点后的字段），分段复用标准文件名中的中间产品编码（保留 `806C`），不改 multipart 实际文件名。非标准名必须在现有派发确认表补齐分段，执行请求可携带 `segment_name`；缺分段或船号在下载/上传前拒绝，已有远端任务的指派重试不重新上传。上传和指派分阶段落库，指派失败重试不重复上传。
- 上传超时或重启中断标记结果待核对，不能盲目重传；保存草稿不下载、上传或回写 PDM。

`FILE_DATABASE_ENABLED=false` 时清单为明确标识的模拟PDM数据；默认 `FILE_SOURCE_MODE=disabled`。
真实 HTTP 下载必须同时启用真实 PDM，不能用模拟记录请求真实文件服务；模拟 PDM/文件也不允许推送真实魔盒。保存草稿不会下载、上传或回写 PDM。

### PDM 目录树与文件查询

文件页依次调用项目、目录和文件接口，页面不会把整库文件一次加载到浏览器：

```text
GET /api/v1/cutting/projects
→ GET /api/v1/cutting/catalogs?project_id=...
→ GET /api/v1/cutting/files?project_id=...&catalog_id=...
```

- 项目来自 `BasicConfig_ProjectInfo`，显示项目名称和船号；文件页首次进入默认只查询“君正25900-9SS”，也可手动改为其他项目名称或船号，每次最多返回20个匹配项目。
- 目录来自 `PDM_NCDocumentCatalog`，通过 `ID / ParentID` 递归展示任意层级，不写死“船体、分段、板材、Gen指令”等名称。
- PDM 中与项目同名的目录根节点会在页面隐藏，避免项目名称重复显示；其子目录保持原始排序和层级。
- 派发历史的状态单元格保留原派发标签；收到可匹配的 `TASK_FINISHED` 回调后，在同一行并排显示绿色“已完成”，悬停查看完成时间和机床。“成功派发时间”后单列“加工完成时间”，读取 `processing_finished_at` 并按图表相同时区显示，无完成时间或无效时间显示 `--`。原派发状态、阶段及首次派发时间不被完成回调覆盖；未收到通知不推测正在加工或已经完成。
- 完成通知按唯一的派发任务 `taskIdentifier` 匹配，实际完成机床与目标机床IP不一致也可确认完成；原目标机床不变，回调机床另存为实际完成信息。模拟、未上传、空标识或无法唯一匹配的通知不更新任务。
- 图表同时展示每日成功派发任务数和加工完成任务数，分别按首次派发时间和魔盒完成时间归日，按配置时区统计真实记录；每条任务计一次，不累加加工件数，重复回调不重复计数。点不同柱子或使用日期选择器时，明细按对应的派发／完成时间筛选，保留原分页与机床过滤。页面可见时每5秒静默更新，回调配置及现场测试见[配置参考](../deployment/配置参考.md#魔盒加工完成回调)。
- 派发历史的“文件位置”在创建派发记录时保存项目名称及目录链（例如 `18600-2 / 船体 / 船体 / 410S / 板材 / Gen指令`），重复的同名目录层级保留，项目根名称不重复添加。该列保持单行，支持拖动调宽和悬停全文；历史查询使用本地记录，不随PDM目录改名变化。未保存该信息的旧记录显示“未记录”，不推测补齐；部署前通过维护工具应用PostgreSQL追加迁移 `005_dispatch_file_location`。
- 点击任一目录后只查询该目录直接关联的 `PDM_DesignDocumentInfo`，右侧按文件名、中间产品、文件格式、版本、操作人、工号和操作时间分页显示，每页20条；可在当前目录内按文件名或中间产品快速查找。
- 每次下载仍绑定具体文档、版本和 `PDM_DocumentFileInfo.FilePath`；同版本存在多条历史物理记录时使用查询稳定选出的最新记录，路径无效时拒绝下载。
- 下载记录保留项目、船号、中间产品、目录链、版本、大小、校验值和操作人，供后续核对与审计；旧记录可能显示“未分类”。

派发需要管理员明确确认，批量选择上限100项；不会因查询条件自动派发，也不回写 PDM 状态。

### 文件保存与安全边界

- 点击保存后，后端按文档ID重新查询 PDM，将版本和路径与页面选择核对，再读取接口。找不到对应版本或列表中的版本、路径已过期时明确报错，不回退其他版本；同版本的历史物理记录不影响重复保存。
- 接口为 `GET /FOWebApi/api/FO/FilePreView`，两个 Query 参数为 `filepath` 和 `contentType=application/octet-stream`；不需 SMB/FTP。
- 使用数据库 `DocumentNo` 作为下载文件名，不拼接版本号；名称缺少扩展名时补用 `FilePath` 的原扩展名，并清理 Windows 不支持的字符。
- 每次保存使用独立目录 `data/cutting-downloads/<下载ID>/<文件名>`，记录进入 SQLite `cutting_downloads`，包含名称、版本、大小、SHA-256、时间和操作人。同名或重试不会覆盖已完成文件。
- Docker 中的文件保存在部署服务器数据卷 `/app/data/cutting-downloads`，供魔盒推送使用。系统不向浏览器提供下载到用户电脑的接口。
- 各页面表格采用按当前内容自动分配列宽的布局，不固定列宽比例、不均分列宽。短字段、时间和数值完整显示，长文件名及说明允许换行，窄屏仅在表格区域横向滚动；分页后新内容自动参与布局，不需要手动调整列宽。
- 保存记录列表只用于查询和追溯；文件选择与派发参数统一在“文件派发”页面完成。当前允许推送 `.GEN` 和 `.TXT` 文件，不提供内容预览、不执行文件内容，也不会自动生成派发任务。
- 页面及保存接口仅管理员可用。推送读取系统文件前会校验路径、大小和 SHA-256；接口错误页、空文件、不完整文件不标记为保存成功。

文件服务认证、传输限制和数据保留参数见 [配置参考](../deployment/配置参考.md)。

## 权限与会话

登录后按角色分流：管理员进入完整管理主站，在“车间报表”查看任务、确认人和确认时间，并可对误确认执行有原因、可追溯的撤销或改派，不能代替工人新增本人确认；工人账号直接进入独立的“我的任务确认”页，不显示领导报表、数据库等管理导航。新增确认和本人撤销 API 限制为工人角色，管理更正和审计查询 API 限制为管理员。

工人确认页右侧提供“我的已确认任务”：默认按当天生产日期统计当前设备下仍归属于登录工人的确认任务，支持最长366天区间及10项分页，展示程序、工程、船名、分段、生产日期和确认时间。窄屏时面板位于任务表下方；历史区间独立于左侧任务筛选，确认、撤销及原页面轮询完成后刷新当前个人区间。已撤销或改派给他人的任务不计入，历史查的是当前有效归属，并非审计流水。

`GET /api/v1/workshop/my-confirmed-tasks?device_id=...&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&page=1&page_size=10` 仅工人角色可读，身份固定取会话，不接受指定他人。查询由 `ConfirmationRepository` 使用同一SQLite读取事务完成总数与分页，按设备、当前确认人及生产日期过滤，优先关联确认所绑定的日报；旧记录未绑定日报时选同设备最新任务快照去重。不查询生产库/BM、不生成日报、不新增表；只查询保留的确认及快照，已清理记录不能恢复。

后端权限与前端角色保持一致，不能通过直接调用 API 绕过菜单限制：

- 公开接口仅包括账号初始化、管理员登录、工人数据库登录、SSO发起与回调、登录状态和健康检查；
- 报告生成/历史/文件、领导报表、数据库管理、连接测试、查询选项和报表设计仅允许管理员访问；
- 车间日报及任务明细允许所有已登录员工查看，任务确认及本人撤销只允许工人账号，撤销他人确认、改派和审计查询只允许管理员；
- 演示数据模式不会绕过登录或管理员权限；
- SQL Server 模式下，SQL 工作台和报表设计在管理员登录之外继续要求独立高强度令牌。

## HTML / PDF 导出

领导、车间和设备报表右上角的“导出报表”下拉框提供“导出 HTML”和“下载 PDF”。
HTML 保留原有生成与历史流程；PDF 生成完成后直接下载，使用与当前查询相同的起止日期和图表类型。
车间页面发起的新导出按已应用日期、设备与工程/船名条件重新查询生产任务，不复用Consumer进程中较早的任务查询缓存；汇总、明细及确认记录使用本次查询结果。旧式无区间的日报导出继续读取原日报快照，已归档文件不自动更新。
领导新导出刷新本期区间汇总及所选自然月趋势；设备新导出刷新任务、任务能耗计算和月度任务数/工时，不复用Consumer旧生产查询缓存。能耗月汇总仍读取已保存的日快照，不因导出触发历史仪表同步。焊接导出沿用现场只读事务，自定义报告沿用完整流式查询；AI成功结果继续按原范围及历史缓存规则复用。
生成结果及历史列表也提供“下载 PDF”，无需重新查询业务数据。PDF 按内容宽高生成连续长页，
包含完整表格、图表与智能分析；首次按需转换已归档 HTML，此后复用同一 PDF。

领导、车间、设备、焊接、告警及自定义报告统一采用领导报告版式：宽屏正文820px，共用页头、标题、执行摘要、指标卡和分析章节样式，窄屏自适应。各业务保留原指标、单位、筛选、数据质量说明及分析契约；自定义报告不额外生成模型分析。关联依据完整展开，不截取前三项。HTML宽表格内部横向滚动；PDF统一210mm页宽，宽表格按可用宽度缩放，保留单行及完整内容，长报告继续按内容高度生成。

运行环境与 Chromium 安装见 [配置参考](../deployment/配置参考.md)。

下载接口：`GET /api/v1/reports/{report_id}/download?device_id=Cutter01&format=pdf`，仅管理员可访问；
省略 `format` 时仍下载 HTML。PDF 转换只读取已归档报告，并阻止渲染页面发起外部网络请求。

## 报表邮件推送

自动推送邮件先按现有 PDF 下载规则将已归档 HTML 渲染为连续长页 PDF，再按144 DPI转换为内嵌 PNG 连续展示；不重新查询生产数据，不重新排列图表与明细，不显示分页、页码、重复页眉页脚或图片间隔。为限制位图内存，超长内容直接按高度分块渲染，每块最多4096像素高，邮件中无缝拼接。图片通过 CID 随邮件发送，无需访问外部图片地址。正文图片按可用宽度等比例显示，文字不能直接复制，小屏查看细节需要放大；交互图表和可复制文字仍在原 HTML 报告中使用。

智能分析输出沿用报告 HTML：新切割简报展示动态发现与完整关联依据，旧四段分析适配同一领导报告版式；邮件沿用归档内容。报告内容或版式变更需重新生成，已归档报告及已发送邮件不追溯修改。

发送前再次核对报告的成功分析状态。旧版本尚未发送且缺少成功分析的邮件转为 `analysis_wait`，保留原文件与邮件记录，另建报告任务；等待模型/缓存成功并生成新报告后，原邮件记录再恢复发送，不增加本次SMTP尝试次数。新报告生成失败时邮件显示失败并可人工重试；部分收件人已接受或结果未知时不自动重生成，保留原接收结果并提示核对。已发送、发送中及结果未知的邮件不进入该修复流程。

计划的“附加报表”仅控制是否同时发送完整 HTML 附件，关闭后仍生成报表正文。纯文字备用正文继续保留。正文渲染复用 PDF 的同机 Chromium 容量、隔离子进程与超时清理；渲染或读取文件失败在 SMTP 提交前按原策略重试，SMTP 结果未知及部分拒收继续沿用现有保护。

PDF生成与分块转图均在原渲染容量和执行期限内完成，临时PDF在转换后清理，不新增报告归档或发送入口。内容越长，邮件体积越大，不截断正文。失败后的重试等待从本次准备/发送结束时计算，包含 Chromium 排队与渲染耗时。自动化页面的两张表随内容展开，不设内部纵向滚动，窄屏仍保留横向滚动、调宽及省略全文查看。发送记录仅展示一次任务名与收件人，完整邮件主题在核对详情中保留。

定时任务支持按任务名称检索；邮件记录通过 `GET /api/v1/automation/deliveries?search=关键词` 在全部记录中检索任务名、邮件主题及原始收件人，不区分英文大小写，关键词按字面值匹配。新检索从第一页开始，翻页与刷新保留已应用关键词，失败保留上次结果。

企业邮箱可能调整正文样式、限制内嵌图片或较长邮件的显示，最终效果需在现场邮箱验收；服务器 Chromium 安装要求见[配置参考](../deployment/配置参考.md)。

## 配置驱动报表设计

当前已移除“报表设计”菜单和页面路由，旧页面地址转回设置首页；已有定义、模板、后端接口及历史数据保留。以下说明用于维护既有接口，不表示当前页面入口：

1. **查询任务**：维护只读 T-SQL、返回字段、字段类型和单位；支持语法校验与数据预览。
2. **报表定义**：选择查询任务和模板，配置周期、明细列、汇总指标、分类轴和图表系列。
3. **模板设计器**：配置标题、页眉标识、主题颜色、页面背景、单双栏布局、表格密度和图表高度，并实时预览。

查询 SQL 支持以下命名参数，执行时会转换为 SQL Server 参数化查询：

- `:machine_no`：必须显式声明的设备范围，由服务端按当前设备绑定
- `:period_start`：所选日/月或显式区间的开始日期
- `:period_end`：所选日/月或显式区间的结束边界（不包含）
- `:report_date`：用户选择的报告日期
- `:project_code`：工程号
- `:ship_no`：船号

既有启用报表定义继续由报告生成接口使用。系统内置的领导、车间和设备报表为只读定义，继续使用原有专用统计管线；内置模板可复制后修改。

自定义报表显式传入区间时，查询必须同时声明 `:period_start`、`:period_end`，实际统计包含开始日和结束日，报告展示相同区间；额外参数中的同名日期不能覆盖已确认的区间。未传区间时继续使用定义的日/月周期。

SQL Server 模式下的令牌与只读边界见 [配置参考](../deployment/配置参考.md)。

报表定义、查询任务和模板均保存在 `data/metadata.db`，每次修改自动递增版本号；已生成的 HTML 仍为单文件离线报告。

## PDM 资料统计

- 管理员入口 `/admin/pdm-statistics`，独立于生产线。沿用文件库绑定的 SQL Server 数据源和配置快照；仅执行只读查询，停用或连接失败明确报错，不回退模拟统计。`POST /api/v1/pdm-statistics/options` 提供按类型、项目、专业联动的筛选字典；`POST /api/v1/pdm-statistics/report` 返回筛选后的表格结果。`GET /api/v1/pdm-statistics/overview` 独立返回全部设备资料、全部详设图纸的文档总数及完成率，页面进入时加载；不接收项目、专业、类型、负责人或日期筛选。每张卡片并列展示按时完成率、总完成率、未完成率，均按文档数量计算；未完成率为（总数－已完成数）÷总数，总数为零显示“—”。卡片完成数按有效实际出图日期有值计，不受表格结束日限制；停用和失败保持明确报错。
- 设备资料五类与详设图纸七类按已核对的 `DesignDocType + PDM_DocumentType.Name` 精确匹配，文档仍通过 `DocumentTypeID` 关联；同名的多个项目类型 ID 不写死。`设备审批表` 对应按设备统计，`设备技术协议` 对应按单协议统计；图纸的 `详设图下发` 对应页面“详设下发图”。泛类型“详细设计”“完工文档”不混入这十二类。
- 数量口径以未作废文档为单位。每个区域可切换计划日期/实际日期，API使用 `date_basis=plan|actual`，默认plan；所选日期为空时回退到另一个日期筛选，非空无效日期不回退。计划为空、实际有值的文档计为已完成及按时完成；两个日期都为空时，不受日期范围限制，每个查询区间均按其余筛选条件计入总数和未完成数。有计划日期的文档，实际日期不晚于所选结束日计为已完成，同时不晚于计划日期计为按计划完成。两种完成率均除以总数，零分母显示“—”；空值含NULL、空串和纯空白，非空无效日期不当作空值或完成。汇总、按项目及按专业使用同一组聚合结果，比例按合计数量重算，不平均子组比例。
- 表格遵循用户提供的原表：标题/日期/范围、两级完成率表头、资料类型纵向合并和分组总计。进入页面默认查询上海时区当月完整区间（1日至月末）。设备资料固定提供五个独立区域：所有项目汇总、所有项目－分专业、所有项目－分项目、单项目－分专业、单专业－分项目；详设图纸提供所有项目汇总一个区域。点击顶部卡片切换类别，只显示当前类别的区域，切换时保留各区域已应用条件和结果。前四种汇总/分组表进入时加载当月结果；设备的两个单项区域初始保留筛选入口，查询后在各自区域内为每个所选项目或专业生成分表，不替换其他区域。每个区域有固定键，卡片使用独立的全部数据统计，不随表格查询变化、不累加展开表；报表中的类型汇总仍表示已提交筛选范围，供分组核对使用。此页按明确要求保留合并表头及分类换行；项目、专业文本单行显示，支持调宽和悬停全文。所有表均保留完整的设备五类/图纸七类，类型筛选只改变数量，不删除模板行。表内专业行固定为“总体、外舾、内装、船体、轮机、电气、船管、工法、总计”，没有数据也保留零值；按专业分表也按这八项名称归组，同名专业跨项目 ID 合并。模板外或关联缺失的专业不追加行或分表、不猜测归并；项目行及按项目分表只展示有效项目，不生成“未填写”。未归组文档仍计入表内总计或全局卡片，表外说明未分配数量。
- 不设页面通用筛选栏，每个独立区域的“筛选”按钮打开本区域弹窗，资料类别和表型固定，不提供跨表型切换，保留时间段及该类全部筛选字段。弹窗草稿与本区域已应用条件分离，取消不提交，查询成功只更新本区域的全部表格及图表，失败保留原结果；区域保留完整多选条件，生成的各分表保留对应项目或专业范围。项目字典独立读取PDM工程表中的有效编号和非空名称，包括尚无匹配文档的项目，不随资料类型、专业缩小；其他字典继续按资料类型、项目及专业联动。项目、专业按账号记忆，更换项目或类型时保留仍有效的专业选择，仅移除字典中失效的专业。负责人每次打开筛选弹窗都按当前范围全选；同一次打开且范围不变时保留手动选择，清空负责人表示不匹配任何文档，取消不改已应用条件。每表采用左侧柱状图、右侧完整展开表格（约4:6）。汇总表横轴为资料类型；分组表则每个资料类型单独作图，横轴为该类下的专业或项目，只使用明细行的按时完成率与总完成率，不把总计重复画柱。小图按右侧对应类型区块的实际位置和高度定位，上下各内缩4px，相邻图统一间隔8px，中心仍与对应表格区块对齐，随列宽、数据及窗口变化重测；项目较少的区块保留320px最小高度供图表阅读。纵轴0～100%，两组柱为按时完成率、总完成率；长项目名称缩略，悬停保留完整名称。无分母保持缺失状态。只隐藏表格内部滚动条，页面整体上下滚动保留；窄屏专项适配暂缓。
- 厂商表 `Custom14` 的现场历史值同时包含 `TRUE/FALSE` 和“是/否”；字典与筛选统一映射成“是/否”，空值保留为未填写，不当作“否”。等级、批次和权重保留文字原值（例如 `B`、`I/II/NA`），不转成数字或零；筛选字典保留实际专业；所有表内专业行和专业分表遵循上述固定八项专业的展示规则。
